ブランチ: {BRANCH}（切り替えない・push しない・マージしない）
結果ファイル: {RESULT_PATH}

## 手順

1. 作業票の「課題」の各 ID を `python .claude/ledger.py issue <ID>` で読む。課題の中身は作業票に写していない＝台帳（ISSUES.md）が正典。
2. 作業票の「範囲」の中だけを変える。
3. 作業票の「受け入れ」のテストを自分でも回す。フルスイートは回さない（コミット前ゲートの範囲だけ）。
4. 台帳の対応欄と、作業票が挙げる版計画・メモリを更新してからコミットする（1 票＝1 コミットが原則）。
5. 結果ファイルに JSON を 1 つ書いて、応答を終える。

## 結果ファイルの形（UTF-8・JSON オブジェクト 1 つ）

{"status": "done", "summary": "何をしたか（1〜3 文）"}
{"status": "blocked", "summary": "どこまで進めたか", "question": "人に決めてほしいこと（選択肢があれば並べる）"}
{"status": "continue", "summary": "どこまで進めたか", "handoff": "済んだこと・次の一手・触りかけのファイル"}
{"status": "failed", "summary": "何が壊れていて、なぜ自分では直せないか"}

## 規則

- 判断が要ったら推測しない。コミットできる所まで閉じて `blocked` と問いを書いて終わる。
- 作業票の範囲の外を変える必要が出たら `blocked`。
- トークン予算の助言（無人モード）が来たら、いまの一手を閉じてコミットし、`continue` と引き継ぎを書いて終わる。
- 受け入れのテストと範囲は、あなたが終わった後に駆動スクリプトが自分で確かめる。`done` と書いても、赤なら差し戻される。
- 結果ファイルを書かずに終わると失敗として扱われる。
