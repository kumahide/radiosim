## 概要・用途

RadioSim Link は、無線回線設計における **現地調査前の概算スクリーニング** に特化したツールです。
TX（送信局）と RX（受信局）の座標・アンテナ高・無線設定を入力すると、国土地理院の標高データを自動取得して地形断面を描画し、リンクバジェットの成立可否を数秒で判定します。

### 主な機能

#### 実行フロー（4 つ）

**★クラス点検の単位**でもあり、欠陥を直すときは「この 4 つ＋地図の 5 面すべてに当てはまらないか」を必ず問う。

| フロー | 実装 | 入力の source of truth |
| --- | --- | --- |
| **1 回線** | `simulation.py` | 左の列の入力欄 |
| **複数経路** | `batch.py` | 面の表（CSV の読み書き） |
| **条件探索（比較 / スイープ）** | `scenario.py` | 固定した経路＋条件列。**DEM 取得 1 回＋純計算 N 回**（計算が 2 フェーズであることを使う） |
| **中継経路** | `multihop.py` | waypoint 列（地点）。区間は導出。再生中継モデルで**全体判定は min**（最も余裕の少ない区間）、内訳と両方を出力 |

画面は `webui/`（Edge のアプリモードで開くローカルの HTTP サーバー）。4 つの面は右の上で切り替え、計算は `webui/worker.py` が裏のスレッドで回す。

#### 地図

- **地図**（`webui/static/app.js`・Leaflet）: 右の上に 1 つ。端点のピン（T・R）をドラッグして座標を入れる（離したときに 1 回だけ計算を頼む）・右上で背景地図を切り替える・断面図にマウスを載せると、その地点が地図に出る

#### 計算モデル（`models.py`。純関数・副作用ゼロ）

- 国土地理院 DEM PNG タイル（5m / 10m メッシュ）から地形断面を自動生成
- 地球曲率補正（標準大気 K = 4/3 固定）
- Bullington 法 / Fresnel-Kirchhoff 法による回折損計算
- 植生減衰（LoS 侵入深さモデル）
- 環境損失（市街地 / 郊外 / 農村 / 見通し の 4 区分）
- 降雨減衰（ITU-R P.838-3）・大気減衰（ITU-R P.676-13 Annex 2）

#### 出力（`report/` が本文を作り、画面が選んだ場所へ書く。すべてヘッドレス）

- 作業面の結果の CSV（`summary.csv`・`hops.csv`・`scenario.csv`）。列は出力契約（`core/output_contract.py`）に従う
- KML（1 回線は `path.kml`・複数経路は `summary.kml`）
- 地図と断面図の PNG
- 結果フォルダは作らない（成果物は 1 つずつ、選んだ場所へ保存する）。A4 の帳票は Link には無い（RadioSim Pro の機能）

#### 入力の再利用

- **プロジェクトファイル（`.rsproj`）**: 座標・全パラメータ・バッチ行・条件探索の条件・waypoint 列を 1 ファイルに束ねて保存／再開（**結果と app 設定は含めない**）
- **案件情報（案件名・自由メモ）**: 新しい画面に入力欄は無い。開いた `.rsproj` の案件情報は、保存し直しても持ち越す

#### 画面

- 判定の帯（判定の語・詳細・前提を振った幅）と、左の列の内訳（リンクバジェット）
- 断面図（`webui/profile.py` が描く材料を作る）。マウスを載せると地図と連動する
- 座標表記の切り替え（DD / DMS・`coords.py` は純関数）
- 日本語 / 英語 UI 切替（`i18n.py` が単一ソース）＋**利用者が言語を足せる**（`lang/<コード>.json`）。`t()` は前からキー単位で英語へフォールバックするので、外部の表は**上書きできた分だけ**効く。⛔ プラグイン機構は作らない（読むのは JSON 1 種類だけ）。⚠️ **成果物の語（`html_*` / `pl_*`）は開かない**。出力契約が利用者ごとに変わるためである。**差し込み（`{n}` など）が英語と違うキーは採用せず、そのことを起動時に画面で言う**（採用すると `str.format` が `KeyError` を投げてその画面で落ちるため、黙って壊れさせない）
- テーマ（ライト / ダーク / システム自動）。切り替えは「設定」の枠（⚙）

### 精度の位置付け

組み込みの国土地理院 DEM の水平解像度は 5〜10m です。計算を実測で較正していないので、回折損に「±何 dB」という誤差の幅は名乗りません。前提（植生高・環境区分・回折の方式など）を振ると判定が裏返る回線は、判定を `REVIEW`（現地確認を推奨）にして示します——これは誤差の幅ではなく、結果が前提にどれだけ依存するか（前提依存性）です。⚠️ **地形の解像度と DEM 標高の誤差は振っていません**。複数の障害物が重なる経路の合成損失も、実測とも基準実装とも突き合わせていません（後述）。
本ツールはあくまで「現地調査が必要かどうかを判断する」スクリーニング用途を目的としており、回線設計の最終判断には使用しないでください。

## Windows バイナリのビルド

python.org の **embeddable Python** に、依存ライブラリと製品のソースを並べた配布フォルダを作ります。自前の exe は作らず、起動には Python Software Foundation の署名がある `pythonw.exe -m webui` を使います（PyInstaller で作った exe が Smart App Control に 2 回止められたため、Link 1.0 で切り替えました）。検査と手順はすべて `buildtools/build_link.py` にあり、`build.bat` はその入口です。

### 前提条件

- **環境変数 `RADIOSIM_PYTHON`**（**必須**）: テストを走らせている仮想環境の `python.exe`。依存ライブラリはこの Python の site-packages から写すので、検証した版と配る版が同じになります。→ [開発環境のセットアップ](#開発環境のセットアップ)
- **環境変数 `RADIOSIM_EMBED_ZIP`**（**必須**）: python.org の embeddable の zip。`RADIOSIM_PYTHON` と同じ版のものを指定します（`vendor\` の拡張モジュールがその版用なので、版が違えば止まります）
- ⚠️ **ビルドに使う Python に Tk 9 が要ります**。アイコンを `webui/static/brand.svg` から Tk 9 の SVG 読み込みで描くためです（Windows 版の Python 3.15 は Tk 9.0 を同梱しています。確かめ方は `python -c "import tkinter; print(tkinter.TkVersion)"`）。配布物の中では Tk を使いません

> **なぜ環境変数で明示させるのか**：以前 `build.bat` は `PATH` の Python でビルドしており、pytest が検証した環境と推移的依存が食い違ったまま配布していました（TLS の CA バンドルを含む）。探索やフォールバックを持たせると食い違っても黙って成功するため、**未設定なら止める**設計にしています。

### ビルド手順

```bat
build.bat
```

`buildtools/build_link.py` は次の順に進み、どこかで食い違えばビルドを中止します。

| ステップ | 内容 |
| --- | --- |
| 1 | `RADIOSIM_PYTHON` で走っていること、`RADIOSIM_EMBED_ZIP` の実体と版を確かめる |
| 2 | embeddable を展開し、`python3XX._pth` で読む場所を標準ライブラリ・`vendor`・`app` だけにする |
| 3 | 実行時の依存を `vendor\` へ写す。`requirements.txt` の固定と版が違うとき、依存の依存が写す物の中で閉じていないときは中止する |
| 4 | `core/`・`report/`・`webui/` を `app\` へ写して `.pyc` を作り、同梱文書（マニュアル日英から辿れる `.md` と絵）・`LICENSE`・`icon.ico`・`version.txt` を置く |
| 5 | **同梱漏れの検査**。作った木の `python.exe` で製品の全モジュールを読み、読めなければ中止する（開発機には全部入っているので、ソースから実行しても漏れは見えない） |
| 6 | `portable.txt` と起動用の `RadioSimLink.cmd` を足して zip に固める |

`build.bat clean` は再生成可能な生成物・キャッシュ・ログ・配布 zip を一掃します。

- **残すもの**: 仮想環境と、**リポジトリ直下の** `terrain_cache/` `results/` `basemap_pale/`（ソース実行で貯めたデータで、取り直しが高価、または利用者のもの）
- **消すもの**: ビルド出力の下は**すべて**。⚠️ **配布フォルダから起動したアプリが自分の隣に作った `terrain_cache/` `results/` も消えます**（これらはビルド出力の一部で、通常のビルドでも作り直されます）。

### 出力

リポジトリ直下の `dist/`。

```
dist/
├── RadioSimLink/                  ← 配布フォルダ
│   ├── python.exe / pythonw.exe   ← embeddable Python（標準ライブラリは zip）
│   ├── vendor/                    ← 実行時の依存ライブラリ
│   ├── app/                       ← core / report / webui
│   ├── docs/                      ← 同梱文書
│   └── LICENSE / icon.ico / version.txt
├── RadioSimLink-<版>.zip          ← ポータブル版
└── RadioSimLink-Setup-<版>.exe    ← build.bat installer のとき
```

版は `core/version.py` の `APP_VERSION` から実行時に取得します（この手順書に版を書き写さない。写すと版を上げた日に嘘になる）。

### 配布パッケージの作成

`build.bat`（引数なし、または `build.bat link`）が **ZIP まで自動で作ります**。配布フォルダに `portable.txt` と `RadioSimLink.cmd` を足して `dist\RadioSimLink-<版>.zip` へ固めるところまでがビルドの一部です。zip を展開した利用者は `RadioSimLink.cmd` から起動します。

`core.config.is_portable()` は `portable.txt` の有無で分岐します（無ければ「インストール先が書込禁止かもしれない」と見なし、OS 標準の場所〔`%APPDATA%` 等〕へ書きます）。

### インストーラのビルド（Inno Setup）

```bat
build.bat installer
```

同じ配布フォルダを作ったうえで、`installer/link.iss`（Inno Setup）を使って `RadioSimLink-Setup-<版>.exe` を生成します（`build.bat link-installer` も同じ）。**`portable.txt` は同梱しません**（インストール先は常に非ポータブル扱いで、設定・キャッシュ・ログ・結果は OS 標準の場所）。

- **前提条件**: [Inno Setup 7](https://jrsoftware.org/isinfo.php) 導入済み（`winget install JRSoftware.InnoSetup.7`）＋環境変数 `RADIOSIM_ISCC` に `ISCC.exe` のフルパスを設定。導入先はユーザー単位なら `%LOCALAPPDATA%\Programs\Inno Setup 7\ISCC.exe`、マシン単位なら `C:\Program Files (x86)\Inno Setup 7\ISCC.exe` です（設定例は cmd なら `setx RADIOSIM_ISCC "C:\...\ISCC.exe"`、PowerShell なら `setx RADIOSIM_ISCC "$env:LOCALAPPDATA\Programs\Inno Setup 7\ISCC.exe"`。**`%LOCALAPPDATA%` は PowerShell では展開されない**ので、そのまま貼るとリテラルが保存されます）。未設定・実体なしならビルドを中止します。
  - **配布ビルドは Inno Setup 7 系で作ります**。ビルドがコンパイラの版を確かめ、7 でなければ中止します。**黙って 6 で作った配布物が出てしまう**のを防ぐためのゲートです（上流の更新は 6.7.3〔2026-05-26〕を最後に 7 系へ移っています）。意図して別の版で作るときだけ `RADIOSIM_ISCC_ANY_VERSION=1` を宣言してください。
- **インストール先の既定**: `{autopf}\RadioSim Link`（`PrivilegesRequired=lowest`。管理者権限が無ければユーザー配下、あればユーザーが選べる）。
- **出力先**: 配布フォルダと同じ `dist/`（`RadioSimLink-Setup-<版>.exe`）。
- **署名**: `RADIOSIM_SIGNTOOL` が定義済みならインストーラに署名します（未定義なら未署名のまま）。現在の配布物は未署名です。⚠️ **「未署名では導入がブロックされる」状況は 2026-09-07 に実際に確認しました。** Windows 11 の Smart App Control（⚠️ **クリーンインストールした環境に限らない**・対象地域は限られる）が、インストーラが `%TEMP%` へ展開する本体を実行拒否します（下のトラブルシューティング表）。**証明書の取得は見送ると決定しました（2026-09-11）。** 自己署名では通らず（Smart App Control は信頼された署名者か評価を要求します）、無償の OV 系サービス（SignPath Foundation）や EV も文書上は通る見込みが立ちましたが、単独開発者が毎リリース外部依存を1つ増やすコストに見合わないと判断したためです。ポータブル版 ZIP の案内が恒久的な仕様です。3.x では ZIP を展開した自前の exe も止められました（2026-10-24 に開発機で確認）。Link 1.0 からは起動に署名のある `pythonw.exe` を使いますが、それでも止まった場合は組織の管理者に相談するよう案内しています（利用者マニュアルの同じ節）。

### 製品名と外の包み

上に載る非公開の層は、この道具を借りて自分の配布を作ります。`--product` で配布の名前（フォルダ・zip・インストーラ・起動の `.cmd`・スタートメニュー）が替わり、`--license` でその許諾を `LICENSE` の隣へ足します。`--package 名前=フォルダ` と `--entry 名前` で、このリポジトリの外の包みを `app\` へ足して起動の口をそちらへ替えます（公開側のコードは上に載る層の名前を知りません）。⛔ インストーラの AppId とインストール先は替えません。同じ場所の Lite を置き換え、設定とキャッシュを引き継ぐためです。

### トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| `ModuleNotFoundError` が起動時に発生 | ビルドの同梱漏れの検査は、関数の中の import までは読みません。足りない配布物を `buildtools/build_link.py` の依存の一覧（外の包みなら `--runtime-dist`）に足してビルドし直す |
| エラーメッセージが見えない | 配布フォルダでコマンドプロンプトから `python.exe -m webui` を起こすと、例外がそこに出る（`pythonw.exe` はコンソールを持たない） |
| SmartScreen 警告（配布先） | 署名なしインストーラのため正常。「詳細情報」→「実行」で続行 |
| インストーラが「エラー 4551: アプリケーション制御ポリシーによってこのファイルがブロックされました」で中止（配布先） | **SmartScreen ではなく実行拒否で続行不可**。Windows 11 の Smart App Control（⚠️ **クリーンインストールした環境に限らない**。有効になる経路は複数あり、**そこは数えない**。判定に要るのは「その機械で今オンかどうか」だけ）または組織のアプリケーション制御が、未署名の `setup.tmp`（Inno Setup が `%TEMP%` へ展開する本体）を弾いている。**MOTW ではないので「ブロックの解除」も効かない。** 恒久的な案内はポータブル版 ZIP（署名は見送りと決定済み）。それでも止まったら組織の管理者へ相談するよう案内する。詳細は `docs/manual_ja.md` の「インストーラが Windows に止められたとき」 |
| 上記が自分の環境で起きているか確かめたい | `Get-WinEvent -LogName Microsoft-Windows-CodeIntegrity/Operational` の EventID `3033` / `3077` にブロックされたファイル名とポリシー ID が残る。Smart App Control の状態は `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` の `VerifiedAndReputablePolicyState`（`0`=オフ / `1`=オン・適用 / `2`=評価モード） |

## 動作環境・依存ライブラリ

| 項目           | 要件                                                  |
| -------------- | ----------------------------------------------------- |
| OS             | Windows 10/11（macOS / Linux でも動作しますが未検証） |
| Python         | 3.12 以上（固定版 numpy 2.5 の要件。3.15 で動作確認済み） |
| インターネット | DEM 取得時に必要（取得済みタイルはキャッシュ）        |

### 必要ライブラリ

```
python -m pip install -r requirements.txt
```

**版は [`requirements.txt`](../requirements.txt) が単一ソース**です（固定することでソース実行と配布バイナリで同じ版が入る）。名前を並べて入れると版が固定されず、下表と二重管理になります。

| ライブラリ | 用途 |
| ---------- | ---- |
| numpy      | 地形・伝搬計算のベクトル演算 |
| matplotlib | Pro の帳票の図（公開側のアプリは使いません。Pro が同じ固定版を使うため一覧に残しています） |
| requests   | 国土地理院タイルと更新の確認の HTTP 取得 |
| Pillow     | PNG タイル画像のデコードと、成果物の地図画像の描画 |
| markdown   | 「設定」の枠の「ドキュメントを開く」で文書を HTML にして開く（省略可。無ければ `.md` をそのまま開きます） |
| truststore | 企業プロキシ環境での SSL 証明書検証（省略可、なくても動作します） |

## ファイル構成

```
radiosim/
│   # 層はディレクトリで表す。依存は webui → report → core の一方向。
│   # 2 つの層から使われるものは「下」へ置く（`shared/` のような箱は作らない）。
│
├── core/                 # 土台。計算・データ・設定。tkinter も matplotlib も引かない
│   ├── models.py         # 純粋計算ロジック（副作用ゼロ）
│   ├── diffraction.py    # 回折損（Bullington 等価ナイフエッジ。球面回折は未実装）
```

## インストール・起動（ソースから実行）

```bash
# リポジトリの中へ移る（requirements.txt と webui/ はここにある）
cd radiosim

# 依存ライブラリのインストール（版は requirements.txt が単一ソース。固定して配布物と揃える）
python -m pip install -r requirements.txt

# テスト・ビルドもする場合は開発用も（PYYAML_FORCE_LIBYAML=0＝bandit が使う PyYAML には
# Python 3.15 向けの wheel が無くソースから組むので、C 拡張を作らせない。下の「開発環境のセットアップ」と同じ）
PYYAML_FORCE_LIBYAML=0 python -m pip install -r requirements-dev.txt

# 起動（Microsoft Edge のアプリモードで画面が開く）
python -m webui
```

初回起動時にプロジェクトルートへ以下のディレクトリが自動作成されます。

| ディレクトリ       | 内容                           |
| ------------------ | ------------------------------ |
| `terrain_cache/` | DEM タイルのディスクキャッシュ |

Link は結果フォルダ（`results/`）へ書きません。成果物は保存のたびに選んだ場所へ 1 つずつ書きます。`results/` は 3.x の結果を探す口として、「設定」の枠の「結果フォルダを開く」で開けます（無ければ作ってから開く）。

## 「設定」の枠

メニューバーはありません。上の帯の右端の **「設定」ボタン（歯車）** が小さな枠を開き、**設定 / ファイル / ヘルプ** の 3 つの群が並びます。枠の中身（今の値・選べる値・字）はサーバーが `webui/settings.py` の `payload` で渡し、画面（`webui/static/app.js`）はそれだけで枠を組みます。ラベルは `i18n.py` の辞書が単一ソース。以下がその全項目です。

- **1 つ替えるたびに保存**（`settings.apply` が検査してから `config.save_app` を呼ぶ）。枠の OK は閉じるだけ。
- 押した結果と失敗の理由は、枠の下の 1 文で返す（ダイアログは出さない）。
- **背景地図**（`basemap_layer`）は枠ではなく地図の右上の欄で替える（保存の口は同じ `settings.apply`）→ [地図](#地図)。
- **プロジェクトの開く・保存**は枠ではなく、右の列の上（面の切り替えの隣）の道具 → [プロジェクトファイル（.rsproj）](#プロジェクトファイルrsproj)。

### 設定

選択内容は `radiosim_conf.json` に保存されます（実装は `webui/settings.py`・扱う鍵は `KEYS`）。

| 項目                  | 選択肢                      | 説明                                                          |
| --------------------- | --------------------------- | --------------------------------------------------------------- |
| 言語                  | 日本語 / English（＋自分で足した言語） | UI の表示言語。替えると画面を読み直す（画面の字は起動時の表から組むため） |
| 訳のひな形を書き出す... | —                         | 訳せる全キー＋英語の値を `_template.json` で書き出す（`webui/files.py` の `write_lang_template`）。ブラウザの保存の画面は初期フォルダを選べないので、`USER_LANG_DIR` へ直に書き、上書きはしない → [表示言語を自分で足す](../docs/manual_ja.md#表示言語を自分で足す) |
| テーマ                | システム / ライト / ダーク  | 画面の明暗                                                      |
| 座標の表示形式              | 十進度（DD）/ 度分秒（DMS） | 座標の**表示**表記（`coords.py`）→ 下記                        |
| プロキシ URL          | URL 入力                    | HTTP プロキシを明示指定（空欄 = OS のプロキシ設定を使用）→ 下記 |
| 起動時に更新を確認 | チェック | 既定オフ（`update_check_auto`＝`"on"` のときだけ）。起動時に `webui/notices.py` の `start_update_check` が背景のスレッドで `update_check.auto_due()` を見て、真なら試みた日（`update_check_last`）を**打つ前に**保存して 1 回問い合わせる＝失敗しても同じ日に 2 度目は打たない。新しい版があるときだけ地図の上の帯で知らせ、最新・失敗はログだけ |
| プレリリースも知らせる | チェック | `update_check_prerelease`＝`"on"`／`"off"` は利用者が選んだ値、既定の `""` は「いまの版で決まる」（`update_check.want_prerelease()`＝正式ならオフ・RC/a/b ならオン）。チェックの印はその解いた値を映す。触ったら以後は `"on"`／`"off"` に固定。手動と起動時の両方に効く |

### ファイル

**ファイル／OS の外へ出る操作**の置き場（実装は `webui/files.py`）。

| 項目                  | 説明                                                                     |
| --------------------- | -------------------------------------------------------------------------- |
| パラメータ読込...     | 設定ファイルから**シミュレーション条件だけ**を入力の変更にする（`sim_changes`＝app の鍵は捨てる） |
| アプリ設定を読込む... | 設定ファイルから、「設定」の枠が持つ app の鍵（言語・テーマ・座標の表示形式・背景・プロキシ）**だけ**を取り込む（`settings.apply_many`） |
| 結果フォルダを開く    | `results/` をエクスプローラーで開く（無ければ作ってから開く）。Link はここへ書かない＝3.x の結果を探す口 |
| 全キャッシュ削除...   | 取得済みの DEM / 地図タイルを削除（枠の中で確認）。DEM のソースが 2 つ以上のときだけ、ソースごとに選ばせる |

> **「パラメータ読込」と「アプリ設定を読込む」は領分が排他**。前者はシミュレーション条件、後者は「設定」の枠の項目。**互いに相手を書き換えません**（他人のファイルを開いた瞬間に表示言語やネットワーク設定が変わらないための設計）。

| 診断パッケージを保存... | `webui/support.py` が保存前に何が入るかを枠の中に並べ（環境事実は既定でチェック・`results/` の成果物は既定でチェックなし）、`core/diagnostics.py` が ZIP を組み立てる。画面から来た名前は一覧の中だけ受ける → [ユーザーマニュアルのヘルプセクション](../docs/manual_ja.md#ヘルプ) |
| 更新の確認... | `core/update_check.py` が押したときだけ GitHub Releases へ問い合わせる（プロキシ設定に従う）。最新・新しい版・失敗のどれも枠の下の 1 文で返す。ダウンロードと入れ替えはしない |
| バージョン情報 | `version.py` の版数を枠の下の 1 文で示す              |

### 起動時の知らせ

`webui/notices.py`。読み込めなかった訳・宣言ファイルの報告と、起動時の更新の確認で見つけた新しい版を、**地図の上の閉じられる帯**に出す（作業を止めない・起動のたびに出す）。文を組む関数は純関数で、試験が直に呼ぶ。

### 座標の表示形式（DD / DMS）

**表記（表示）の設定であって入力モードではありません。** 入力は `coords.parse_pair` が DD / DMS の双方を寛容に受理し、計算前に必ず DD へ正規化されます（`simulation.SimParams` へ渡る値は常に DD）。

欄の書き直しは画面（`webui/static/app.js` の `reformatCoords`）が持ち、走るのは**表記の切替時・アプリ設定の読込時・地図のピンを動かしたとき（選んだ表記で書き戻す）**。対象は送信・受信の端点の欄だけで、**読めなければ原文が残る**（整形されないこと自体が「読めていない」の合図）。⚠️ 複数経路・条件探索・中継経路の表の座標は書き直さない（打った形のまま持ち、実行と保存のときに `webui/sheets.py` が型へ直す）。

### プロキシ設定

企業ネットワーク等でプロキシを経由して DEM タイルを取得する場合は、「設定」の枠の **プロキシ URL** へ入力してください。

```
http://proxy.example.com:8080
```

- 確定すると即時反映されます（`dem.set_proxy` と地形の覚えの破棄。アプリの再起動は不要）
- 空欄にすると OS のプロキシ設定（システム設定 / 環境変数）に戻ります
- SSL インターセプトを行う企業プロキシ向けに `truststore` による Windows 証明書ストア連携も有効です
- プロキシ未設定で標高サーバーへ一切到達できない場合、**連続失敗で打ち切り**て知らせます（平坦な地形として黙って完走しない）

## 地図

<img src="images/shot_map.png" width="600" alt="地図上に送信点・受信点と経路が表示された画面">

地図は画面の右の上に 1 つだけあり、4 つの面で共有します（`webui/static/app.js`・Leaflet）。別のウィンドウは開きません。コアのシミュレーションは地図なしで完結し、地図は入力と結果を見るための補助です。

- **1 回線**: 送信点と受信点にピン（T・R）を立て、2 点を線で結びます。初めて 2 点がそろったとき、経路全体が入るように寄せます。**ピンをドラッグすると座標が入ります**。ドラッグの間は左の列の座標欄と線だけが動き、**離したときに 1 回だけ計算を頼みます**（地形の取得は端点が決まったときだけ）。座標欄が source of truth で、欄を書き換えるとピンがその位置へ移ります
- **複数経路・条件探索・中継経路**: 作業面の表の各件を、送信点から受信点への線で判定の色に塗って描きます。表で選んだ件は太くなり、地図の線を押すと表のその行が選ばれます。条件探索は全件が同じ経路なので 1 本だけ描きます。全件がそろって座標の組が変わったときに、全体が入るように寄せます
- **断面図との連動**: 断面図にマウスを載せると、その地点が地図に印で出ます。逆に、地図の線（1 回線の線と、作業面で選んだ件の線）に載せると、断面図の側にその地点が出ます
- **背景地図**: 右上の欄で切り替えます（淡色・航空写真と、宣言ファイルで足した背景地図）。選んだものは設定の `basemap_layer` に保存し、保存する地図の PNG の背景も同じものになります。タイルは手元のサーバー（`webui/server.py` の `/tile/`）を通して取り、キャッシュに残します。表示義務のある出典は地図の右下に出します

範囲を指定して DEM タイルを先に取っておく処理は `core/dem_prefetch.py` に残っています（新しい画面からは呼びません）。取得済みで**読めるもの**は取り直しません（外部サーバー配慮）。全キャッシュの削除は「設定」の枠のファイル（全キャッシュ削除...）です。

## 使い方 — 1 回線

<img src="images/shot_profile.png" width="720" alt="地形断面グラフ。送受信点を結ぶ見通し線とフレネル第 1 ゾーンが地形に重ねて描かれ、遮蔽区間と受信レベル・マージンが表示されている">

起動すると 1 回線の面が開きます。**実行ボタンはありません**。左の列の欄を変えると、少し待って（`DEBOUNCE_MS`）変えた欄だけをサーバーへ送り（`/api/inputs`）、計算のスレッド（`webui/worker.py`）がその版の入力で計算し直します。

### 1. 左の列の入力欄

欄の並びと語は `webui/server.py` の `_FORM` が単一ソースで、画面（`webui/static/app.js`）はそれを並べるだけです。

| 群 | 欄 |
| --- | --- |
| サイト情報 | 送信座標・受信座標（緯度, 経度）・送信／受信アンテナ高（m） |
| 無線設定 | 周波数（MHz）・送信電力（dBm）・送信／受信アンテナ利得（dBi）・受信感度（dBm） |
| 伝搬環境 | 環境区分（市街地 / 郊外 / 農村 / 見通し）・植生高（m）・降雨強度（mm/h） |
| 詳細（畳んである） | 回折モデル・地形の解像度・DEM ソース（選べるソースが 2 つ以上のときだけ出す） |

- 座標の 2 欄は十進度でも度分秒でも読みます（[座標の表示形式（DD / DMS）](#座標の表示形式dd--dms)）。空にしたときだけ書式の例を薄字で出します
- 値域は欄の吹き出しにあり、外れた値は計算に進まず上の帯が「入力待ち」と理由の 1 文になります（検査は `config.validate_config`・範囲は[入力パラメータ詳細](#入力パラメータ詳細)）
- ライス K の欄は出しません。入力の集合（`webui/state.py`）には残り、プロジェクトファイルの読み書きでは値を保ちます
- **地形の解像度**は高 約4m 画素 / 中 約8m 画素 / 低 20m 間隔 の 3 段階。⚠️ **段階の名前は「標本を置く画素の大きさ」**であって、*どの標高データを読むか*ではありません（標高は段階によらず**取れる中でいちばん細かい層**から返ります）。画素の実寸は緯度で 3.3〜4.4m と振れるので「約」です。**入れるのは段階だけで、点数はアプリが解きます**。「高」「中」は**経路が通る DEM 画素の縁ごと**に標本を置くので**等間隔ではなく**、点数は経路の長さ・向き・緯度から決まります（「低」だけは 20m の等間隔で、*粗いが速い*段階として画素を飛ばします）。ただし点数が上限に当たる極端に長い経路では、「高」「中」も等間隔に落ちます。既定は「中」

欄の下の **リンクバジェット** の表は、EIRP から総損失・受信レベル・受信感度・マージンまでを足し引きの順に並べます（行は `_BREAKDOWN`・値は見出しの同じ名前の数）。判定が古い間は薄く出し、今の入力の値ではないことを示します。

### 2. 地形の取得と計算

計算のスレッドは 1 本で、1 回の手順は「版の写しを取る → 検査 → 地形 → 計算 → その版の見出しとして載せる」です。

1. **地形**: 端点・標本・段階・DEM ソースから作る鍵（`engine.terrain_key`）が手元の地形と同じなら取り直しません。違えば `engine.fetch_terrain` で標本ごとに標高を取ります（取ったタイルはディスクのキャッシュに残る）。取得中に地形の鍵が変わる入力が来たら古い取得を取り消し、地形に効かない欄だけが変わったときは取り終えてから最新の入力で計算します
2. **計算**: `engine.calculate` は地形の上の純計算で、ネットワークへ出ません。アンテナ高や送信電力を変えても地形は取り直さないので、すぐ判定が返ります

標高サーバーへ届かないときは、上の帯が「地形なし」と理由の 1 文になります（平坦な地形として黙って計算しない）。

> **地形データの日付**: キャッシュ済みのタイルは取り直さないため、地形に載る取得日（`TerrainProfile.dem_acquired`）は実行日ではなく**標高を読んだタイルをこの PC に保存した日**（キャッシュファイルの更新日時・`dem.tile_acquired_date`）です。経路上で日付が複数にまたがるときは最古〜最新の範囲になります。この値の算出はネットワークへ出ません。新しいタイルで計算し直したいときは、「設定」の枠の全キャッシュ削除で消してから計算させます。

### 3. 上の帯の判定

画面の上の帯が判定の語（OK / REVIEW / NG / ERROR）・マージン・受信レベルを出します。前提を振った幅があるときはその幅を、REVIEW のときは判定を裏返す前提を並べます（字はサーバーが作る）。🔑 **帯の判定は、いま画面に出ている入力から計算したものだけ**です。計算中は「判定を更新しています…」と取得の進み具合を出し、古い判定を残しません。

### 4. 断面図

右の下に、地形断面を canvas で描きます（`app.js` の `drawProfile`・形はサーバーの `webui/profile.py` が帳票と同じ線で作る）。

| 表示要素 | 説明 |
| --- | --- |
| 地形 | 地球曲率補正済みの地表（下端から塗る） |
| 植生 | 地表の上に植生高 |
| 見通し線 | 送受信アンテナの先端を結ぶ破線 |
| 第1フレネルゾーン | 標本の位置で見通し線の ±F1 の帯 |
| 両端の縦棒 | 送信・受信アンテナ（足元から先端まで） |

マウスを載せると、その地点の距離と地表の標高を出し、地図にも同じ地点の印を出します（[地図](#地図)）。

### 5. 入力の持ち運び

入力は `radiosim_conf.json` へ**書き戻しません**（起動時に読むだけで、3.x の最後の入力から始まる）。作業を残すのは右の列の上の **プロジェクトを保存...**（[プロジェクトファイル（.rsproj）](#プロジェクトファイルrsproj)）、他の設定ファイルから条件だけを取り込むのは「設定」の枠の[ファイル](#ファイル)（**パラメータ読込...**）です。結果の保存は[保存パッケージ](#保存パッケージ)を参照してください。

## 使い方 — 複数経路

<img src="images/shot_batch.png" width="720" alt="複数経路の入力表。1 行 1 経路で、実行後の判定（OK / NG）と水平距離が各行に返っている">

右の上の面の切り替えで **複数経路** を選ぶと、地図の下に表が出ます。表を直すと少し待って面の入力を丸ごと送り（`/api/inputs` の `sheets`）、全行を 1 件ずつ取得して計算します（`engine.run_paths`）。結果は済んだ行から表の右端（判定・マージン・受信レベル）へ返り、全行がそろうと上の帯に全体の語と語ごとの件数が出ます。

### 設計思想 — 共通の入力は 1 つ、行は経路だけ

無線機と環境の欄は 4 つの面で 1 つです（左の列）。複数経路の面では**端点とアンテナ高の欄を隠し**（各行が持つ）、残りの欄が全行の共通設定になります。行の周波数・利得が空欄なら共通設定を継ぎます。表は打った字のまま持ち（`webui/sheets.py`）、型へは実行と保存のときに直します。

### 入力方法

**手動入力**: 表のセルに ID・座標・アンテナ高・周波数・送受信利得・備考を打ちます。表に出すのは CSV の 9 列（`_BATCH_SHOWN`）で、実測の列は表に出さずに持つだけです。

- **+ 行を追加**: 末尾に空の行を足します（ID は今ある数の ID の次）
- **× 削除**: 選んだ行を（選んでいなければ末尾を）消します
- **CSVインポート**: CSV を読んで表を差し替えます（`/api/batch_csv`）。見出しの誤りは表の上に 1 文で出します

⚠️ **行の誤りはその行だけ ERROR** にし、ほかの行は計算します（`sheets.batch_plan`）。誤りの 1 文は行に載せ、その行を選ぶと断面図の場所に出ます。

#### CSV フォーマット

必須列: `id, start, end, h_tx, h_rx`

省略可能列: `freq, gain_tx, gain_rx, note, meas_dbm, meas_method, feeder_loss_db, env_class`

```csv
id,start,end,h_tx,h_rx,freq,gain_tx,gain_rx,note,meas_dbm,meas_method,feeder_loss_db,env_class
path01,"34.54, 132.41","34.53, 132.40",30.0,10.0,2400,12.5,8.0,メイン回線,-78.5,spot,2.1,suburban
path02,"34.55, 132.42","34.52, 132.39",20.0,15.0,,,,サブ回線,,,,
```

- `start` / `end` は「緯度, 経度」の形式でダブルクォートで囲んでください
- `freq` / `gain_tx` / `gain_rx` を省略した場合は共通設定の値が使われます（**リンク識別属性**として経路ごとに変えられる）。環境区分・降雨強度・回折モデルは共通設定で一括指定します
- `gain_tx` / `gain_rx` 列のない旧 CSV もそのまま読めます（後方互換・利得は共通設定を継承）
- 列名は**大小文字と前後の空白を区別しません**（`ID,Start,…` でも読めます）。`id` は**大小文字を区別せず**一意である必要があります（`p01` と `P01` は重複として弾かれます）
- `meas_dbm` / `meas_method` / `feeder_loss_db` / `env_class` は実測突合せ用の任意列（列の単一ソースは `core/batch_csv_schema.py` の `CSV_COLUMNS`。読み込んだ値は `batch.PathRow` の属性に入る）。層別（環境区分×帯域×距離帯）の残差統計は `core/residuals.py` が計算し、表にして載せるのは Pro の複数経路のサマリ帳票です（スポット測定を統計から外す `compute_layered_stats(exclude_spot=True)` も Pro 側から使う）。`meas_method` は `spot` / `mean` の想定値。**記録は測定時にしかできない**ので、利用者向けの手順は[マニュアルの「実測との突合せに使う場合の記録項目」](manual_ja.md#実測との突合せに使う場合の記録項目)を参照

### 地図と断面図

地図には各行の送信点から受信点への線を判定の色で描き、行を選ぶと太くなります。地図の線を押すとその行が選ばれ、選んだ行の断面図を 1 件だけサーバーから取ります（`/api/profile`・全件の断面は見出しに載せない）。

### 実行の取り消し

🔑 **実行中に入力の版が進めば、走っている全件を取り消して新しい版でやり直します**（表の 1 字を直しても、走っている全件は古い入力の結果になるため）。1 回線の「地形の鍵が違うときだけ取り消す」とは規則が違います。

## 使い方 — 条件探索（比較 / スイープ）

<img src="images/shot_scenario.png" width="620" alt="条件探索の比較画面。1 本の経路に対し周波数と利得を変えた 4 条件の受信レベルとマージンが並び、最後の条件だけ NG になっている">

右の上の面の切り替えで **条件探索** を選びます。**1 本の確定した経路を、条件を変えて掘る**面で、経路は左の列の入力（1 回線と同じ）、計算側は `core/scenario.py` が持ちます。操作手順は [manual_ja.md](manual_ja.md) が詳しいので、ここでは実装の勘所を挙げます。

- **地形は 1 回線と共有する**: 条件探索は左の列の入力の地形の上で `scenario.evaluate()` を回します。地形の鍵が同じなら取り直さないので、条件を振り直しても DEM の再取得は起きません（これがこの面の使い方そのもの）。評価は純計算なので、全件をそろえてから 1 回で載せます
- **条件は「差分」で持つ**: `Condition` はベースからの上書き辞書で、変えられる欄は `scenario.OVERRIDABLE` が単一ソース。**座標と地形の解像度は入っていません**（経路そのものを比べるのは複数経路の仕事）。比較は最大 `MAX_COMPARE_CONDITIONS` 件
- **ベースは左の列**: 比較の表の先頭の「ベース」の行は左の列の値を映すだけで、表では打てません。条件の空欄はベースを踏襲し、空欄にはベースの値を薄字で出します
- **比較とスイープは同じ計算路を通る**: 表の上の切り替えで比較（ベース＋条件）とスイープ（1 軸 N 点）を選びます。スイープは軸・開始・終了・点数だけを持ち、`webui/sheets.py` の `conditions` が `linspace_values()` → `sweep_conditions(axis, values)` で `Condition` の列に落としてから `evaluate()` に渡します。軸は `SWEEP_AXES`、点数は `MAX_SWEEP_POINTS` が上限。**分岐しているのは入力の作り方だけ**で、評価と結果型（`ScenarioRun` / `ScenarioPoint`）は 1 本です
- **検証は DEM 取得より前**: `validate_base()` はベース値を取得前に弾きます（取得後に落ちると待ち時間を捨てさせる）。条件側は `Condition` が自分で検査済み
- **地図は 1 本**: 全件が同じ経路なので、地図には線を 1 本だけ描きます（選んだ件の語の色・選んでいなければ全体の語の色）。断面は全件が同じ地形で、アンテナ高の上書きだけが線を変えます
- 取得から帳票までを通す `run_scenario()`（`Phase` / `Phases` で取得・計算・成果物の重みを宣言して進捗を出す）も `core/scenario.py` に残っています。新しい画面は使いません

## 使い方 — 中継経路

<img src="images/shot_multihop.png" width="620" alt="中継経路の画面。送信点・中継点・受信点の 3 地点と、区間ごとの受信レベル・マージン・判定が表に返っている">

右の上の面の切り替えで **中継経路** を選びます。**再生中継**（受けて送り直す）前提で、区間ごとに独立したリンクバジェットを計算します。モデルは `report/multihop.py`・実行は `webui/worker.py`（区間を 1 件ずつ計算して `MultiHopRun` にまとめる）。表の上に経路 ID と備考、下に地点の表（名前・座標・高さ）と区間ごとの設定の表（周波数・送受信利得・空欄は共通設定を継ぐ）が並びます。

- **経路は点列＋接続規則で持つ**: `MultiHopPath` は `Waypoint` の列と区間ごとの `HopRF` を持ち、区間は `links(path)` が導出します（並びの意味を各所で書かない）。**高さは `Waypoint` にだけ**あり——中継点のアンテナは 1 本なので、前の区間の受信高と次の区間の送信高を別々に持てない形にしてあります。上限は `MAX_HOPS`（地点は `webui/sheets.py` の `MAX_WAYPOINTS`）
- **トポロジーの宣言は 1 か所**: `TOPOLOGIES` に鎖と星があり、**実際に走れるのは `SUPPORTED_TOPOLOGIES` だけ**。読む・書く・実行するの 3 層がこの 1 つを参照し、ゲートは `require_runnable()`。集約（`ok` / `worst` / `overall_margin`）は**鎖の意味論**なので、鎖以外では黙って数字を返さず止めます（星の min は意味を持たない）
- **実行層は複数経路と同じ**: `hop_rows(path)` が区間を `batch.PathRow` へ落とし、計算のスレッドが複数経路と同じ `engine.run_paths()` に流します。⚠️ **1 区間 = 1 回の DEM 取得**なので取得量は区間数に比例します（隣接区間は端点を共有するのでタイルのキャッシュは効きます）。地点の形の誤りは鎖全体を「入力待ち」にします（複数経路の行ごとの ERROR とは違う）
- **判定の単一ソースは `batch.PathResult.status`**: 計算に失敗した区間はここで OK から外れます。全体判定は「一番余裕の少ない区間」で、**損失は足し合わせません**
- **全体の語は `verdict.aggregate()` が返す**: 区間と同じ語で、NG＞REVIEW＞OK、**`ERROR` の区間が 1 つでもあれば全体も `ERROR`**。⛔ `run.ok` の真偽から語を組み立てないでください——`ok` は「鎖が成立したか」しか答えられないので、判定不能が不成立に潰れ、区間の表と件数の数え方と食い違います
- **地点の追加と削除で区間の設定をずらさない**: 「＋ 地点を追加」は末尾に足し、「− 中継点を削除」は焦点のある地点（無ければ末尾）と、**その地点に入ってくる区間の設定**を一緒に落とします。区間の設定は位置で持つので、地点だけを消すと後ろの区間の周波数・利得が 1 つずれ、**画面は自然なまま別の区間の設定で計算します**
- **中継点は「置く」もので「動かして探る」ものではありません**: 動かすたびに新しい取得が走るため、高さや条件を振るのは条件探索の役目です

## 計算モデル詳細

### 地球曲率補正

実際の電波伝搬では大気の屈折により電波は地球の曲率より大きく曲がります。これを等価地球半径係数 K でモデル化します。本ツールでは標準大気（K = 4/3 ≈ 1.333）を内部固定値として使用します。

```
等価地球半径 Re = R_earth × K  （K = 4/3 固定）
曲率補正量 Δh(d) = d × (D - d) / (2 × Re)  [m]
```

| K の値       | 意味                                 |
| ------------ | ------------------------------------ |
| 4/3 ≈ 1.333 | 標準大気（本ツール使用値）           |
| K > 4/3      | 大気ダクト（電波がより大きく曲がる） |
| K < 4/3      | 負の屈折（電波が地面側に曲がる）     |

### Fresnel ゾーン

電波は幾何光学的な直線だけでなく、その周囲の楕円体状の領域（Fresnel ゾーン）を伝搬します。第 1 Fresnel ゾーンが地形・植生に遮蔽されると回折損が発生します。

```
r₁(d) = √(λ × d₁ × d₂ / (d₁ + d₂))
```

### 回折損

#### Bullington 法（デフォルト・ITU-R P.526 §4.5.1）

複数の障害物をまとめて 1 枚の**等価ナイフエッジ**に置き換えるモデルです。両端から地形を見た仰角が最大の点へ引いた 2 本の接線の交点を障害物の位置とし、標準の補正項 `(1 - exp(-Luc/6)) × (10 + 0.02 × d[km])` を掛けます。

🔑 **3.0 で従来の独自 Deygout 実装から差し替えました**（履歴は「既知の制限」）。理由は精度ではなく**連続性**です。従来の実装は「障害物を数える」構成だったため、**植生高やアンテナ高を 1m 動かすだけで障害物の枚数が変わり、回折損が 84 dB 跳ぶ**ことがありました（アンテナを 1m 上げたら 84 dB 悪くなる）。等価ナイフエッジの位置は地形が動けば連続に動くので、この跳びが構造的に起きません。

⚠️ **「ITU-R P.526 準拠」とも「P.452 準拠」とも名乗りません**。採ったのは P.526 §4.5.1 の**この 1 手法だけ**で、P.452 §4.2.1 の完全法（Delta-Bullington）が足す**球面回折の項**も、clutter も ducting も持ちません。⇒ **標準の手法と同じ値にはなりません**（上の「既知の制限」を参照）。

#### Fresnel-Kirchhoff 損失 J(ν)

```
J(ν) = max(0, 6.9 + 20 × log₁₀(√((ν - 0.1)² + 1) + ν - 0.1))  [dB]  （ν > -0.8）
J(ν) = 0                                                          （ν ≤ -0.8）
```

#### Single 法

全サンプル点の ν を計算し、最大値のみで J(ν) を算出するシンプルなモデルです。

### 植生減衰

LoS 線が植生頂点に侵入した深さから経験的に推定します。

```
侵入深さ(d)   = clip(veg_top(d) - LoS(d), 0, 植生高)
重み(d)       = clip(侵入深さ / r₁(d), 0, 1)
有効植生長    = Σᵢ [(重み(dᵢ) + 重み(dᵢ₊₁)) / 2 × (dᵢ₊₁ − dᵢ)]
Veg Loss      = min(有効植生長 × coeff, 45 dB)
```

> **有効植生長は、隣り合う標本の間の実際の距離で積みます**（台形則。`np.trapezoid(重み, d)`）。
> 標本は等間隔とは限らないため、「重みの合計 × 一定の間隔」では求めません。両端の標本が
> 受け持つのは半区間ずつです（3.0 で是正）。

> ⚠️ **侵入深さの上限は植生高です。** 電波が植生の中を通る厚みは高々キャノピー高であり、
> それを超える分は地表そのものが見通しを切った量で、回折損の担当です。
> **植生高 0m なら植生減衰は必ず 0 dB**になります（3.0 で是正）。

| 周波数帯   | coeff（`v2`＝Link 1.0 の方式） | coeff（`v1`＝3.9.x の方式） |
| ---------- | ------------------------------ | --------------------------- |
| 1 GHz 未満 | 0.20 × f^0.7                  | 0.12 × f^0.5               |
| 1〜6 GHz   | 0.20 × f^0.7                  | 0.20 × f^0.7               |
| 6 GHz 以上 | 0.35 × f^0.9                  | 0.35 × f^0.9               |

> ⚠️ **Link 1.0（計算プロファイル `v2`）で 1 GHz 未満の係数を変えました。** 1 GHz 未満の枝（`0.12 × f^0.5`）をやめ、
> 1〜6 GHz の式を 1 GHz 未満にも使います。ITU-R P.833 の実測（106 MHz〜2.1 GHz）が 1 本の式（`0.194 × f^0.70`）に載り、
> 1〜6 GHz の式とほぼ同じだったためです（1 GHz で式を切り替える根拠が無く、切り替えると 1 GHz の前後で係数が 1.67 倍跳んでいました）。
> **1 GHz 未満の植生減衰は大きくなります。** 検証用の 32 経路を 922 MHz・植生高 3 m で計算すると、植生減衰が立つ 15 本で
> +0.00〜+14.87 dB（中央値 +6.04 dB）大きくなります（上限 45 dB に張り付いた 2 本は動きません）。
> ⚠️ **6 GHz の境目はそのままです**（境目の向こう側の実測が無いため）。6 GHz 以上で植生高を入れた回線には、
> 帳票に「境目で値が跳ぶ（未検証）」の注記が載ります。3.x で保存したプロジェクトを開いたとき（`v1`）は、3.9.x の係数のままです。

### 環境損失

地形・植生損失では捉えきれないマルチパス・散乱等を経験的に補正します。

```
Env Loss = base + slant_dist × dist_c
```

> ⚠️ **遮蔽に由来する量（F1 遮蔽率・回折損）は含みません**。地形が見通しを切ったことは
> 回折損がすでに表しており、環境損失に再び換算すると二重計上になるためです（3.0 で除外）。

| 環境区分 | base | dist_c | min | max  |
| -------- | ---- | ------ | --- | ---- |
| 市街地   | 10.0 | 1.20   | 6.0 | 30.0 |
| 郊外     | 6.0  | 0.80   | 3.0 | 30.0 |
| 農村     | 4.0  | 0.50   | 2.0 | 25.0 |
| 見通し   | 2.0  | 0.30   | 1.0 | 15.0 |

### 降雨減衰（ITU-R P.838-3）

```
γ_R = k × R^α  [dB/km]
Rain Loss = γ_R × d_slant
```

2.4 GHz では降雨の影響は非常に小さく（100 mm/h で約 0.1 dB/km 程度）、実用的な影響が出るのはおおむね 10 GHz 以上からです。

### 大気減衰（ITU-R P.676-13 Annex 2 簡易式）

```
γ_total = γ_O₂ + γ_H₂O  [dB/km]
Gas Loss = γ_total × d_slant
```

### リンクバジェット

```
EIRP      = P_tx + G_tx                             [dBm]
FSPL      = 20×log₁₀(d) + 20×log₁₀(f) - 147.55   [dB]
Total Loss = FSPL + Diff + Veg + Env + Rain + Gas   [dB]
P_rx      = EIRP + G_rx - Total Loss                [dBm]
Act Margin = P_rx - Sensitivity                     [dB]
Status    = OK（≥ 0 dB）/ NG（< 0 dB）                 ← v1（3.9 の方式）
            v2 は前提を振って裏返れば REVIEW・地形の取得に失敗した標本があれば ERROR
```

### 使用データソース

| レイヤー ID   | 解像度               | ズーム | カバレッジ     |
| ------------- | -------------------- | ------ | -------------- |
| `dem5a_png` | 5m（航空レーザ測量） | 15     | 都市部・山地   |

`dem5a_png` → `dem5b_png` → `dem_png` の順に試みます。上位レイヤーが 404 のとき、または画素がデータ欠損 `(128, 0, 0)` かちょうど 0 m `(0, 0, 0)` のときは次のレイヤーに降格します。範囲の事前取得も、下のレイヤーを取るか・残すかを同じ条件で決めます。通常の事前取得も、10m のタイルが無い位置ではキャッシュ済みの 5m のタイルの中身を読み、同じ条件で判定し直します（3.8 から）。3.7 より前に事前取得した範囲で 0 m の画素の下のレイヤーが欠けていても、これで埋まります。

### キャッシュ戦略

- **タイル事前取得**: シミュレーション実行時に TX/RX のバウンディングボックス内の全タイルを事前にディスクキャッシュへ保存（オフライン利用・複数経路の実行の高速化に寄与）。**組み込みの国土地理院を選んでいるときだけ**で、宣言した DEM ソースでは飛ばす（キャッシュ管理の範囲ダウンロード・強制再取得は 3.6 から全ソース対応）
- **メモリキャッシュ**: プロセス内にタイルを保持（キー: `(layer_id, xtile, ytile)`）
- **ディスクキャッシュ**: `terrain_cache/{layer_id}/{xtile}/{ytile}.png` に保存、セッションをまたいで有効。宣言ファイルで足した DEM ソースは 3.6 から `terrain_cache/external/{source_id}/{定義のハッシュ}/{layer_id}/…` に分けて置きます（`core/dem.py` の `DEM_EXTERNAL_SUBDIR`。組み込みの名前と重ならないようにするため）
- **地形キャッシュ**: 同じ TX/RX 座標・サンプル数・解像度の段階・DEM ソースなら DEM 再取得をスキップ。キャッシュの削除・強制再取得は無効化の世代番号（`core/dem.py` の `_cache_epoch`）を進め、世代の違う項目は使いません（取得中に世代が進んだ結果も登録しません）

### 出力列の仕様（出力契約）と変更規約

集計スクリプトや表計算の数式は、**列の名前と並びをそのまま参照します**。そこでこのアプリは、成果物 CSV の**ファイル名・列名・列の並び・値の書式を「契約」として扱い**、次の規約で運用します（3.0 で明文化）。

- **列の追加は末尾のみ。** 既存の列の位置は動かしません（位置で読む相手が居るため）。
- **列の削除・改名・意味の変更は、1 つ前の版で予告してから。** 予告は CHANGELOG と本書の両方に載せます（片方だけだと、配布版だけを見る方に届きません）。
- **値の書式（単位・桁・頭打ち）も契約です。** 単位を変えるときは列名も変えます（例: 2.5 の `slant_km` → `slant_m`）。名前が変われば、古い数式は黙って通らず落ちます。
- **ファイル名も契約です。** 「1 行が何を表すか」が変わるときは、列を足さずに**別のファイル**にします（例: 中継経路の `hops.csv` は、`summary.csv` に区間の列を足す代わりに切り出したものです）。

⚠️ **この規約は「二度と変えない」約束ではなく、変えるときに通る道です。**

> 📣 **RadioSim Link 1.0 で変わったこと（3.4〜3.9.1 で予告したもの・変更規約 2）**:
> - **判定（`status`）列を 4 語にしました**（`OK` / `NG` / `REVIEW` / `ERROR`）。列名・位置と、`OK` / `NG` を分けるマージン 0 dB の線は変えていません。変えたのは、その線に当てるマージンです。予告では「悲観側の前提でも成立なら OK・楽観側の前提でも不成立なら NG」と書きましたが、実際には前提を振った**全部の組み合わせ**のマージンで決めます。`OK` は**評価した前提の範囲で成立**という意味で、地形の解像度と DEM 標高の誤差は振っていません。地形の取得が通信の失敗で欠けた標本があれば `ERROR` にします（標高データのタイルが無い海上・日本域外の標本は標高 0 m として計算し、その点数を帳票に名乗ります）。語の定義は下の「判定（`status`）の 4 語」にあります。**`ERROR` は改名していません。** `status == "OK"` のように 2 値で読んでいる場合は、`REVIEW` を「要確認」として別に扱ってください（`OK` 以外を一律に不成立とすると、現地確認で通るはずの回線まで落とします）。
> - **末尾に列を 2 つ足しました**（計算プロファイル ID `calc_profile` と入力設定のハッシュ `input_hash`）。既存の列は動いていません。
> - **画面・帳票の「ライスKファクター」（現在値）の欄をなくしました。** 回折損から `initial_k − diff_loss / 3` で求める表示専用の推定値でしたが、係数「3」に出典が無く、回折損が 30 dB を超える経路では製品の既定（初期値 10）で常に 0 を出していました（3.4 で実測）。計算には使っていなかったので、ほかの数字は動きません。
> - **1 GHz 未満の植生減衰が大きくなりました。** 予告の外の変更です（列の契約は変わらないので、変更規約 2 の対象ではありません）が、数字が動くので書きます。中身と量は [植生減衰](#植生減衰) にあります。地形の標高の読み方（標本の間を補間する）と、地形で遮られた経路の地面反射の幅（回折損が乗っている経路には出さない）も変えました。
> - **数字がどれだけ動いたか。** 検証用の 31 経路を、3.9.x の方式（計算プロファイル `v1`）と Link 1.0 の方式（`v2`）で比べました。`REVIEW` に移った経路は 13 本（`OK` から 9 本・`NG` から 4 本）、`OK` と `NG` の間で裏返った経路は 0 本です。マージンが動いた経路は 28 本で、1 dB を超えて動いたのは 9 本（最も下がった経路は植生減衰で −13.32 dB、最も上がった経路は回折損で +11.62 dB）です。
> - 3.x で保存したプロジェクトファイルは、3.9.x の方式（`v1`）のまま開きます（→ [プロジェクトファイル](#プロジェクトファイルrsproj)）。

> 🔴 **3.9 での変更（3.8 で予告）**: **ソースから実行する場合の対応 Python の下限を 3.11 → 3.12 に上げました。** 配布 exe を使っている場合は影響ありません。あわせて `numpy` を 2.4.4 から 2.5.3 へ更新しました。更新の前後で計算結果と成果物 CSV を比べ、値が 1 つも変わらないことを確かめています（比べ方は `experiments/numeric_parity_probe.py`）。

⚠️ **自由文字列の列（`note` / `error` / `label`）は、`=` `+` `@` などで始まる値に `'` を前置します**（表計算ソフトが数式として解釈するのを防ぐため）。数値として読める値（マージンのような負の数）はそのまま書きます。

**判定（`status`）の 4 語**（計算プロファイル `v2`）: 判定は、既定の前提で計算したマージン 1 つではなく、前提を振った全部の組み合わせのマージンで決めます。振る前提は、植生高（入力値の ±30%）・環境区分（隣の区分まで）・回折の方式（single と Bullington）・回折損と植生減衰の合成（和と大きいほう）の全組み合わせと、地面反射の振れ幅（打ち消し合う側から強め合う側まで）・陸のデータ欠損の画素を前後の標高で埋め直した計算の 3 つです。

- `OK` は、**評価した前提の範囲で成立**することを表します（どの組み合わせでもマージン ≥ 0 dB）。地形の解像度と DEM 標高の誤差は振っていないので、そこまでは保証しません。
- `NG` は、どの組み合わせでもマージンが 0 dB 未満であることを表します。
- `REVIEW` は、**前提の取り方で結果が裏返る**ことを表します（既定の前提で成立しても最悪の組で不成立、または既定の前提で不成立でも最良の組で成立）。現地での確認を推奨します。
- `ERROR` は、判定できなかったことを表します（計算か成果物の生成に失敗した、または地形の取得が通信の失敗で欠けた標本がある）。
- `margin_db` などの数値列は、どの語でも既定の前提で計算した値です。
- `OK` 以外を一律に不成立として読む処理は、`REVIEW` の回線まで落とします。`REVIEW` は「要確認」として別に扱ってください。
- 計算プロファイル `v1`（3.9.x の計算方式。計算プロファイルを持たない旧プロジェクトを開いたときに使います）は、3.9.x と同じく既定の前提のマージンだけで `OK` / `NG` を決め、`REVIEW` を出しません。

## プロジェクトファイル（.rsproj）

**入力一式**を 1 つの JSON へ束ねる形式です。ランチャーの **ファイル → プロジェクトを開く / 保存** から読み書きします（実装は [`project.py`](../report/project.py)。ヘッドレス・tkinter に依存しません）。

### 束ねる範囲

| セクション | 内容 |
| --- | --- |
| `meta` | 案件名・自由メモ |
| `params` | ランチャーの sim パラメータ（座標は DD 固定） |
| `batch` | バッチ行（`PathRow` の属性名で持つ。CSV 列名ではない） |
| `scenario` | 条件探索の条件セット（**画面の文字列のまま**） |
| `multihop` | 中継経路の waypoint 列と区間別 RF |

**含めないもの**: 計算結果（`results/` 側の仕事）、app 設定（テーマ・言語・プロキシ・座標表示形式）、ウィンドウの位置/大きさ/開閉状態。app 設定を含めないのは、他人のプロジェクトを開いた瞬間に言語やプロキシが変わるのを防ぐためで、読み書きの両側で `config.select_sim` を通します。

### 互換性の規則

- `schema_version` は**ドキュメント全体で整数 1 つ**（セクションごとの版は持ちません）。
- **未知キーは無視／欠損キーは既定値／自分より新しい版は拒否**（`config.load_config` と同じ流儀）。
- `app_version` / `saved_at` は刻印であって**読込の判定には使いません**。
- **セクションが無い（キーが無い）ことは「そのウィンドウの情報を持たない」**であって「空のウィンドウ」ではありません。したがって読込側は触らず、保存側は前回値を持ち越します（複数経路のウィンドウを閉じただけで行が消えたファイルを書かないため）。
- 数値として読めない値（NaN / Inf）は書きません。該当するセクションは保存せず、UI がその旨を知らせます（規格外の JSON を作らない）。

### 読込の流儀

読込時は**ウィンドウを閉じません**（2.7 で変更）。開いているウィンドウの上に `views.dialogs.show_notice` のバーを出し、**押されたときだけ** `replace_rows` / `apply_project_spec` / `apply_project_path` で差し替えます。

⚠️ **既存の `↻ ランチャーから更新` には載せていません**。あちらは凍結バー（共通設定・案件情報）だけを触り、利用者が入れた行・地点には手を出さないボタンで、そこへ差し替えを足すと「共通設定を更新するつもりで押したら行が消えた」という事故になります。

⚠️ **セクションが `None` のファイルではバーを出しません。** `None` は「そのウィンドウの情報を持たない」で、空にする指示ではないためです（出すと「取り込む」が全消しとして働く）。取り込まないままウィンドウを閉じた場合は、閉じる処理が今までどおりそのウィンドウのセクションを持ち越すので、**画面に見えていた内容が残ります**（凍結方式と同じ向き）。

## 開発環境のセットアップ

依存の宣言は **2 ファイルに分かれています**（別アプリの実測補助の分は下の表の 3 行目）。

| ファイル | 中身 | 配布物に入るか |
| --- | --- | --- |
| `requirements.txt` | 実行時依存（numpy / matplotlib / requests …） | **入る** |
| `requirements-dev.txt` | テスト・静的解析・パッケージング（pytest / pytest-cov / pyright / ruff / bandit / PyInstaller） | **入らない** |
| `requirements-field.txt` | 実測補助（`apps/field`）がシリアルポートを開くための pyserial。テストには要らない（CI も入れない） | **入らない**（本体とは別のアプリ） |

分けてある理由は、開発用の道具を実行時依存に混ぜると EXE に同梱され得るためです。**どちらもピン留め**しており、`requirements-dev.txt` の PyInstaller は配布 EXE のブートローダを決めるため、ここが無ピンだと「その日の最新」で焼いた出荷物になります。

```bat
rem 1. 仮想環境を作る（クラウド同期フォルダの外に置くのを推奨。venv は絶対パスが
rem    焼き込まれるため同期しても他マシンでは使えず、同期する意味がありません）。
rem    ⚠️ Tk 9 を同梱する Python から作ること（ビルドの「前提条件」）。PATH の先頭の
rem    python が Tk 8.6 だと、その venv では build.bat が止まります。Python の版は
rem    py ランチャーで明示し、先に Tk の版が 9.0 と出ることを確かめます
py -3.15 -c "import tkinter; print(tkinter.TkVersion)"
py -3.15 -m venv D:\dev\radiosim\venv

rem 2. 実行時依存と開発依存の両方を、ピンどおりに入れる。
rem    PYYAML_FORCE_LIBYAML=0＝bandit が使う PyYAML には Python 3.15 向けの wheel が
rem    無くソースから組むので、C 拡張を作らせない（C コンパイラが無くても止まらない。CI も同じ）
set PYYAML_FORCE_LIBYAML=0
D:\dev\radiosim\venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt

rem 3. その python.exe を「検証にもビルドにも使う唯一の環境」として宣言する
rem    （設定後はシェルを開き直すこと。ビルドとローカル QA フックがこれを見ます）
setx RADIOSIM_PYTHON D:\dev\radiosim\venv\Scripts\python.exe
```

`tests/test_env_consistency.py` が、pytest を走らせている環境の実版と `requirements.txt` のピンの一致を検証します（ずれた瞬間にテストが落ちます）。

宣言したあとは、**アプリの起動もその python で行ってください**。

```powershell
& "$env:RADIOSIM_PYTHON" main.py
```

宣言と違う python で起動した場合は、警告をログと標準エラー出力に出して**そのまま起動します**（止めません）。同じ版の Python でもライブラリの版だけが違う状態は起こり得るため、「起動できたから同じ環境」とは言えないためです。この警告は環境変数を宣言していない環境（配布版の exe を含む）では出ません。

## テスト

**宣言した環境（`RADIOSIM_PYTHON`）で回してください。**

```powershell
& "$env:RADIOSIM_PYTHON" -m pytest tests/ -v
& "$env:RADIOSIM_PYTHON" -m pytest tests/ --cov
```

> ⚠️ **裸の `python -m pytest` では回さないこと。** 別の環境で回すと依存の版が
> `requirements.txt` のピンとずれ、**検証した版と exe に入る版が食い違います**
> （`build.bat` は宣言された環境で焼きます）。`RADIOSIM_PYTHON` が設定されている
> のに別の Python で pytest を起動すると、`tests/conftest.py` が理由を示して止めます。
> **未設定の環境（CI・他マシンの clone）では何も起きません**ので、そこでは
> `python -m pytest` で構いません。

> 🖥 **表示のない環境（ヘッドレス）では `RADIOSIM_HEADLESS=1` を宣言してください。**
> GUI テストは Tk を起こせないと止まりますが、**宣言があれば skip・無ければ失敗**
> します。表示があるはずの機械で skip へ倒すと、**GUI 配線を 1 つも検査しないまま
> 「緑」**になるためです（2026-08-07 に 112 本中 106 本 skip・終了コード 0 を実測）。
> あわせて、**全体実行の skip が 25% を超えると失敗**します（理由を問わない網）。

### 実装後の検証を 1 コマンドで（`dev-check`）

`pytest` のほかに `bandit` と `git diff --check` が要るので、まとめて回す入口を置いてあります。

```powershell
# 全件。CI と同じくカバレッジゲートも掛かる（手で全体の緑を確かめるとき）
& "$env:RADIOSIM_PYTHON" buildtools/dev_check.py

# 実装の反復中は範囲を明示する
& "$env:RADIOSIM_PYTHON" buildtools/dev_check.py --tests tests/test_multihop.py
```

- **コミット前ゲートとは別の入口です。** Claude Code のフック（`tools/qa-hook/pre-commit-gate.mjs`）は `git commit` のたびに、変更した面に応じて部分テストかフルスイートを自動で選び、`git push` の前は必ず木全体の合格を確かめます。合格の記録はテストした中身で照らすので、同じ中身でフルスイートが通っていれば回し直しません。直前のフル合格から版の字（`core/version.py` の `APP_VERSION`）の 1 行だけが変わったときは、コミットも push も版の字を読むテストだけを回します。どちらの前にも、台帳・版計画・メモリの実データの検査（`test_claude_hooks.py -k test_real_`・約 2 秒）を先に走らせます。コミットより先に課題を「済」にしてしまった場合は、全テストの最後ではなく、その場で止まります。`dev_check.py` はフックに頼らず手で回す入口で、範囲は引数だけで決まります。
- **`ruff` と `pyright` はここでは回しません**。どちらも既に `tests/test_repo_hygiene.py` の中から `pytest` が回しているので、別に呼ぶと同じ検査が 2 回走り、対象の指定も 2 か所に割れます。
- **範囲を絞っても `tests/test_repo_hygiene.py` は必ず足されます**。上のとおり静的検査がそこに同居しているためで、外れると *静的検査を 1 つも回さないまま緑* になります。
- **変更ファイルは「足す」ためだけに見ます。「減らす」判断には使いません**（例: `docs/` を触っていれば `test_docs_consistency.py` が足される）。関連テストを推定して減らすと、黙って外れる経路ができるためです。
- **カバレッジゲートは全件のときだけ**掛かります。部分実行に掛けると、回していない層が 0% で数えられて必ず割れます。
- 出力は**検査ごとに 1 行＋落ちた検査の抜粋**です。全文は `--full-output`。

### 動作確認用の設定ファイル（`qa_fixtures/`）

利用者拡張の宣言ファイル（`dem_sources.toml` / `tile_sources.toml`）と、利用者が追加する表示言語のファイル（`lang\` の下）は、ポータブル配置では exe の隣、つまり `dist\RadioSimPro\` から読みます。ここはビルドのたびに作り直されるので、手で置いた確認用の設定は毎回消えます。そこで **正本を `qa_fixtures/` に置き、ビルドの後に配る**ようにしてあります。

```powershell
& "$env:RADIOSIM_PYTHON" buildtools/deploy_qa_fixtures.py            # dist\RadioSimPro\ へ
& "$env:RADIOSIM_PYTHON" buildtools/deploy_qa_fixtures.py --repo     # ソースから起動して確認する場合
& "$env:RADIOSIM_PYTHON" buildtools/deploy_qa_fixtures.py --appdata  # インストーラ版で確認する場合
& "$env:RADIOSIM_PYTHON" buildtools/deploy_qa_fixtures.py --remove   # 配ったものを片付ける
```

- ⛔ **`build.bat` からは呼びません。** ビルドの途中で配ると、確認用の設定が配布 zip とインストーラに入ります。配るのは**ビルドが終わった後**だけです。
- 配置先は**製品のコードに聞きます**（`core.config.USER_DEM_SOURCES_FILE`）。ここに置き場を書き写すと、製品側が動いた日に黙ってずれます。言語ファイル（`qa_fixtures/lang/qa_fr.json`）は配置先の直下ではなく `lang\` の下（`core.config.USER_LANG_DIR` と同じ位置）に置きます。
- 何がどの確認のために入っているかは `qa_fixtures/README.md`。正本は**妥当な宣言だけ**で、誤りをはじくことを確かめるときはコピーを壊して使います（正本が壊れていると、他の確認をするたびに毎回エラー通知が出ます）。
- `tests/test_qa_fixtures.py` が**製品の読み込み器で実際に読んで**検証します。宣言ファイルの書式は版とともに変わるので、正本が古びると「確認したかった機能ではなく設定の誤りを見ている」状態になり、しかも**欄が出ないという同じ見え方**をします。

### 独立レビュー（外部のレビュアーに差分を見せる）

自動ゲートが緑なのは必要条件であって十分条件ではありません。**実装した本人は「何を意図したか」で読む**ので、保証の穴は構造的に見えません。RC・正式の前に、外部のレビュアー（Codex）へ差分を渡します。

```powershell
& tools\codex_review\run.ps1 -Mode code -Base <前のタグ>   # コード面
& tools\codex_review\run.ps1 -Mode docs                    # 文書面
& tools\codex_review\run.ps1 -Mode direction               # 方向性（新しい版の着手前・非ブロッキング）
```

- 入力文は `tools/codex_review/prompt_*.txt` に固定してあり、**実行のたびに書き起こしません**。差し込むのは差分のパスと比較元だけで、観点（「ここを見て」）を混ぜる口がありません。
- 渡すのは `git diff` の生出力です（要約・抜粋しない）。
- 方向性の面は、文書面と同じもの（memory と公開文書）を渡し、入力文（`prompt_direction.txt`）だけが違います。見る軸は、本体と関連プロダクトの計画の整合性・後戻りの懸念・方向性の発散の 3 つです。
- 返答は**読む前に** `.qa/codex_review/round<N>_<mode>_codex_raw.md` へ原文で落ちます。後から要約と原文を突き合わせられます。
- レビュアーには書き込みを許しません（`-s read-only`）。**発見はレビュアー、処方はこちら**——プロジェクトの設計意図を持たないので、処方はしばしば外れます。
- ⚠️ **`read-only` は「書けない」であって「ここしか読めない」ではありません**（canary で実測）。文書面の staging は渡す範囲を*明示*する仕掛けであって、**それ以外を秘匿する保証ではありません**。
- memory の場所は `RADIOSIM_MEMORY_DIR` で宣言できます（未設定ならリポジトリのパスから導出）。

## 既知の制限・注意事項

### 精度

- DEM の水平解像度（組み込みの国土地理院で 5〜10m。宣言した DEM ソースはもっと粗いことがあります）が伝搬計算精度の上限です。建物単体の遮蔽は考慮されません
- Bullington 法は複数障害物の近似です。計算を実測で較正していないので、誤差の幅（±何 dB）は示せません。**複数の障害物が重なる経路の合成損失は、実測とも基準実装とも突き合わせていません**
- 🔴 **回折損は過大にも過小にも出ることがあり、どの経路で信頼できるかを事前に見分ける方法がありません。** 3.0 で回折モデルを **Bullington 等価ナイフエッジ（ITU-R P.526 §4.5.1）** に替え、①山越えで数百〜数千 dB になる**発散**と、②**植生高やアンテナ高を 1m 動かすだけで 84 dB 跳ぶ不連続**（アンテナを 1m 上げたら回折損が 84 dB 増える形）の 2 つを解消しました。ただし**外れる可能性そのものが消えたわけではありません**。①合成損失は、系統の違う 2 手法（Epstein-Peterson 法・従来の独自実装）と並べて桁を確かめただけで、**実測とも基準実装とも突き合わせていません**。②**離れた 2 つ以上の尾根がある経路では小さめに出ます**（この手法の既知の性質で、標準もそれを承知で採っています）。③**単一の丘では、標準の補正項のぶん従来より大きめに出ます**。④**地形の解像度を上げると回折損が増えます**（「低」の 20m 間隔 →「高」の画素の縁ごとで最大 +407%）。⚠️ ただし**「高」の中でさらに細かく刻んでも動きません**。DEM の標高は画素の中で一定の階段状の場なので、**画素の縁に標本を置いた時点で「刻みの細かさ」という自由度そのものが消えます**（実測では 25 万点まで刻んだ収束値 27.014 dB に対し、画素の縁 210 点で 27.02 dB）。⑤**平滑地球の球面回折の項を持たないため**、**低いアンテナで見通し距離を超える長い平坦路**（海上・干潟など）では過小になりえます。⚠️ 3.0 当時の代表 26 経路では 1 本も該当しませんでした（その後コーパスへ足した経路では確かめていません）が、**この製品はその条件を検査していません**。⚠️ **起伏の大きさでも F1 遮蔽率でも、どの経路が外れるかは判定できません**（起伏は予測子ではありません）。⚠️ **F1 遮蔽率は画面・レポート・CSV とも 100% で頭打ち**（内部の生値は 100% を超えます）なので、率の側からは異常に気づけません。
- 🛡 **上の限界に対する自衛策**: **「回折モデル」を `Single` に切り替えてもう一度計算し、2 つの値を見比べてください。**大きく食い違う経路では、**既定（Bullington）の値を信用しないでください**——判定が NG でも、**その NG が正しいかどうかはこの値からは分かりません**。⚠️ **これは「どちらが正しいか」を決める手段ではありません**。2 つの差が大きければ**結果がモデルの選び方に強く依存している**と分かる、という診断です。**差が小さくても正しさは保証されません**（どちらの値も実測や基準実装と突き合わせていないため）。⚠️ `Single` は**複数障害物の合成損失を表現せず**（最大の 1 点しか見ない）、**標準の補正項も掛けない**ので、**Bullington より小さく出ます**。⚠️ これも**真の値との関係は分かりません**（「`Single` 側が安全寄り」という意味ではありません）
- 植生減衰モデルは経験的近似です。樹種・密度・季節変動は考慮されません
- 環境損失係数は経験値であり、特定地域・用途への適合は保証されません

### データカバレッジ

- **組み込みの DEM（国土地理院）は日本国内限定です。** 国土地理院タイルは日本国外をカバーしないため、DEM ソースを国土地理院のまま日本国外の座標を入力すると標高 0m が返ります。利用者は設定フォルダの `dem_sources.toml` 宣言ファイルで外部 DEM ソース（リモート XYZ PNG タイル）を追加でき、その場合は日本国外の標高も取得できます（`core/dem_sources.py`）。地図ウィンドウの背景地図も `tile_sources.toml` で追加でき（`core/tile_sources.py`・3.5〜）、足せば地図クリックでの座標指定は日本国外でも使えます。**組み込みの背景地図（淡色地図・航空写真）自体は国土地理院タイル固定のまま**なので、航空写真での確認は国内限定です。**帳票に貼る経路地図（`report/report_map.py` → `core/dem.py:fetch_basemap_tiles`）は 3.6〜、地図ウィンドウで最後に選んだ背景地図ソース（組み込み `pale`/`photo` または宣言した外部ソースの `source_id`。`core/config.py` の `basemap_layer` へ永続化）に追従する**ため、外部ソースを選べば日本国外でも描かれます（キャッシュは `pale` は従来どおり `terrain_cache/basemap_pale/`、それ以外は `terrain_cache/basemap/<source_id>/` に分離）
- `dem5a_png` / `dem5b_png`（5m）は全国カバーではありません。未整備地域は自動的に `dem_png`（10m）にフォールバックします
- 海上・湖沼・データ欠損箇所は標高 0m として扱います

### 距離

- 実用上は 20 km 以内を推奨します。それを超える距離はスクリーニング用途の精度限界を超えます

### 操作

- グラフウィンドウを開いている間は同じルートのパラメータ変更ができません
- 地形キャッシュはアプリ再起動でリセットされます（ディスクキャッシュはセッションをまたいで有効です）
- **起動中に Windows の表示スケールを変えると、ランチャーをドラッグしている間だけ大きさが漂います**（再起動で直ります）。⚠️ **原因は Tk 側で、アプリからは回避できないことを実測で確認済み**です（10 通り以上試して不発）。**ソースから実行しても同じ**なので、この症状を見ても自分の変更を疑う必要はありません。3.9 で移った Tk 9.0 でも、8.6 と同じ回数で起きることを実測しています（Tk の版を上げても直りません）。症状の詳細は [manual_ja.md](manual_ja.md) の「操作」を参照してください
- **表示スケールの違うモニタを併用すると、メニューバーだけ字の大きさが他とずれることがあります**。バーは Windows が描く HMENU で、そのウィンドウが載っているモニタの倍率に OS が合わせます。一方、アプリの字（Tk の名前付きフォント）はアプリ全体で 1 つの大きさしか持てず、最後に表示環境が変わったウィンドウに全体を合わせています。そのため、別のモニタへ移したウィンドウと移していないウィンドウのどちらかで、バーと中身がずれます。表示だけの問題です
- **表示スケールを変えたあとサインインし直すまで、ドロップダウンのチェック（✓）が太く大きく描かれて文字に重なり、カスケードの矢印（▸）が消えます**（サインインし直せば直ります）。Tk の `win/tkWinMenu.c` がこの 2 つを OEM ビットマップ（`OBM_CHECK`／`OBM_MNARROW`）を `LoadBitmapW` で読んで描いており、その大きさはサインイン時の表示スケール（システム DPI）で決まる一方、字は今のモニタの DPI に合わせて当てているためです。**Tk 8.6 と 9.0 の両方が同じ描き方**なので Tk 9 へ移っても直りません。症状は開発機では、サインインし直していない状態で表示スケールを変えれば再現できます
