![RadioSim Pro](../logo.png)

> ソースから動かす・中身に手を入れる場合は [developer_ja.md](developer_ja.md) を参照してください。

地上無線回線の伝搬特性を現地調査前にスクリーニングするデスクトップシミュレーターです。
国土地理院 DEM（数値標高モデル）を自動取得し、地形断面・回折損・植生減衰・リンクバジェットをリアルタイムに可視化します。

## 概要・用途

RadioSim Pro は、無線回線設計における **現地調査前の概算スクリーニング** に特化したツールです。
TX（送信局）と RX（受信局）の座標・アンテナ高・無線設定を入力すると、国土地理院の標高データを自動取得して地形断面を描画し、リンクバジェットの成立可否を数秒で判定します。

### 主な機能

#### 実行フロー — 「何を調べたいか」で 4 つ

| フロー | 調べたいこと |
| --- | --- |
| **個別シミュレーション** | 1 本の回線が成立するか。地形断面を見ながらアンテナ高・降雨強度をその場で振れる |
| **複数経路** | 多数の回線をまとめて。CSV での入出力に対応 |
| **条件探索（比較 / スイープ）** | **1 本の経路を掘る**。条件を変えた結果を並べて比較（ベース＋最大 5 条件）／1 軸を N 点振って「どこで足りるようになるか」を折れ線＋表で確認。地形の取得は 1 回だけ |
| **中継経路** | 直接届かない回線を中継点で継ぐ。中継点は最大 7 つで、区間ごとにリンクバジェットを計算。**全体の可否は一番苦しい区間**で決まる（再生中継＝中継点で受けて送り直す方式） |

#### 地図

- **地図**（3 モード）: 地図クリックで座標入力／地図から複数経路へ経路を連続追加／DEM キャッシュの可視化・事前取得・削除

#### 計算モデル

- 国土地理院 DEM PNG タイル（5m / 10m メッシュ）から地形断面を自動生成
- 地球曲率補正（標準大気 K = 4/3 固定）
- Deygout 法 / Fresnel-Kirchhoff 法による回折損計算
- 植生減衰（LoS 侵入深さモデル）
- 環境損失（市街地 / 郊外 / 農村 / 見通し の 4 区分）
- 降雨減衰（ITU-R P.838-3）・大気減衰（ITU-R P.676-13 Annex 2）

#### 出力・レポート

- **A4 レポート（v2）**: 経路ごと / サマリを A4 縦 1 枚の印刷確定枠で出力。ブラウザの Ctrl+P でそのまま PDF 化（追加ソフト不要）。案件名・生成日時・ID を載せた自己同定ヘッダ/フッタ付き
- **アンテナ初期指向 AZ/EL**: 相手局へ正対するための真方位・仰角を経路ごとのレポートに両端ぶん表示（初期値。最終調整は現場の RSSI で）
- **経路地図の自動添付**: TX/RX・経路・距離を地図に重ねて HTML レポートへ埋め込み
- **全経路を 1 枚に俯瞰する地図**（サマリレポート・判定で色分け）
- **一括レポートの一括印刷**: サマリと全経路を 1 文書へ連結した `report_all.html` を自動生成。Ctrl+P 一発で全ページ分の PDF になります
- 結果のパッケージ保存（PNG / CSV / JSON / HTML / KML）

#### 入力の再利用

- **プロジェクトファイル（`.rsproj`）**: 座標・全パラメータ・案件情報・一括の行・条件探索の条件・中継経路を **1 つのファイルに束ねて**保存／再開
- **案件情報（案件名・自由メモ）**: ランチャーで入力すると個別・一括どちらのレポートにも反映

#### 画面

- グラフウィンドウでのアンテナ高・降雨強度リアルタイムスライダー
- 座標表記の切り替え（十進度 DD / 度分秒 DMS）
- 日本語 / 英語 UI 切替
- システム連動ダークモード（ライト / ダーク / システム自動）

### 精度の位置付け

DEM の水平解像度は 5〜10m であり、回折損の実質精度は **±5〜15 dB** 程度です。⚠️ **この範囲が当てはまるのは、回折損が発散していない経路だけです**——発散する経路では誤差はこの桁に収まらず、しかも**どの経路が発散するかを事前に見分けられません**（既知の欠陥・後述）。
本ツールはあくまで「現地調査が必要かどうかを判断する」スクリーニング用途を目的としており、回線設計の最終判断には使用しないでください。

## インストール・起動

### インストール

1. 配布 ZIP ファイルを任意のフォルダに展開してください。
2. 展開されたフォルダを任意の場所に置きます。フォルダを移動しても動作します。

> **注意**: フォルダ内の構成は変更しないでください。`RadioSimPro.exe` 単体では動作しません。

### 起動

`RadioSimPro.exe` をダブルクリックします。

初回起動時、exe と同じフォルダに以下のディレクトリ・ファイルが自動作成されます。

| パス                   | 内容                                                               |
| ---------------------- | ------------------------------------------------------------------ |
| `terrain_cache/`     | DEM タイルのディスクキャッシュ（セッションをまたいで保持されます） |
| `results/`           | 保存パッケージの出力先                                             |
| `radiosim_conf.json` | UI 設定・最後に使用した入力値の保存先                              |

## メニュー

メニューバーは **ファイル / 設定 / ヘルプ** の 3 つです。以下がその全項目です。

### ファイル

ファイルや OS 側へ出る操作をまとめてあります。

| 項目                     | 説明                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| プロジェクトを開く...    | 保存した `.rsproj` を読み込み、入力一式を復元します → [プロジェクトファイル（.rsproj）](#プロジェクトファイルrsproj) |
| プロジェクトを保存...    | 現在の入力一式を `.rsproj` に書き出します → [プロジェクトファイル（.rsproj）](#プロジェクトファイルrsproj) |
| パラメータ読込...        | 過去の設定ファイルから**シミュレーション条件だけ**を入力フォームへ取り込みます         |
| 結果フォルダを開く       | `results/` フォルダをエクスプローラーで開きます                                        |

### 設定

選んだ内容は `radiosim_conf.json` に保存され、次回の起動でも保たれます。

| 項目                 | 選択肢                       | 説明                                                                   |
| -------------------- | ---------------------------- | ------------------------------------------------------------------------ |
| テーマ               | システム / ライト / ダーク   | ウィンドウのカラーテーマ                                                 |
| 言語                 | 日本語 / English（＋自分で足した言語） | UI の表示言語（再起動で反映）→ [表示言語を自分で足す](#表示言語を自分で足す) |
| 座標の表示形式             | 十進度（DD）/ 度分秒（DMS）  | 座標の**表示**表記。→ 下記の注意                                        |
| プロキシ設定...      | URL 入力                     | HTTP プロキシを明示指定（空欄 = OS のプロキシ設定を使用）→ 下記          |
| アプリ設定を読込む... | —                            | 設定ファイルからテーマ・言語・プロキシ**だけ**を取り込みます             |
| 全キャッシュ削除...  | —                            | 取得済みの全 DEM / 地図タイルを削除します（確認あり）                    |

### ヘルプ

| 項目           | 説明                                     |
| -------------- | ------------------------------------------ |
| ドキュメントを開く | このドキュメントをブラウザで表示します     |
| バージョン情報 | インストールされている版数を表示します     |

> **「パラメータ読込」と「アプリ設定を読込む」の違い** — 前者は**シミュレーションの条件**（座標・周波数・アンテナ高など）を、後者は**アプリの見た目と接続設定**（テーマ・言語・プロキシ）を取り込みます。**互いに相手の領分には触りません**ので、他人から受け取ったファイルを読んでも表示言語やネットワーク設定が勝手に変わることはありません。

> **地図はメニューにありません** — ランチャー下部の **「地図」ボタン**から開きます（→ [地図](#地図)）。

### 表示言語を自分で足す

日本語・英語のほかに、**自分で用意した訳を追加できます**。アプリと同じフォルダに `lang` フォルダを作り、`<言語コード>.json` を置いて再起動すると、設定 > 言語のメニューに現れます。

```json
{
  "_name": "Français",
  "btn_run": "Exécuter",
  "menu_help": "Aide"
}
```

- `_name` は**言語メニューに出す名前**です。その言語自身の字で書いてください（自分の言語を探すのは、まだ読めない画面の中だからです）。省略するとファイル名のコードがそのまま出ます。
- **全部を訳す必要はありません。** 書いたキーだけが置き換わり、**残りは英語のまま**出ます。アプリの版が上がって項目が増えても、訳が壊れることはありません。
- キーの一覧は、同梱の `core/i18n.py`（ソース版）を見るのがいちばん確実です。
- **`{n}` や `{dir}` のような差し込みは、英語の文と同じものを同じ数だけ残してください。** 違っていると**そのキーは採用されません**（英語のまま表示されます）。採用しなかったものがあると、起動時にその旨をお知らせします。⚠️ 差し込みを勝手に消した訳をそのまま使うと、その画面を開いた瞬間にアプリが止まります。**採用しないのはそれを防ぐためです。**
- **レポート（HTML）や KML に出る語は対象外**です。成果物の語は読み取る側との約束なので、画面の都合で変えません。
- 同梱の `ja` / `en` は上書きできません（`ja.json` を置いても無視されます）。

> ⚠️ **追加した言語では、画面の見切れを保証できません。** ウィンドウの寸法は日本語と英語の語の長さで検査してあり、それより長い訳語では文字が切れることがあります。**非公式な訳**という位置づけでお使いください。

### 座標の表示形式（DD / DMS）

**表示の表記を選ぶ設定**であって、入力モードの切り替えではありません。

- **入力欄はどちらの書き方でも受け付けます。** 設定が DMS でも `34.8, 132.6`（DD）と打てますし、設定が DD でも `34°48'00.0"N, 132°36'00.0"E` と打てます。計算前に必ず十進度へ揃えられます。
- **表記の切り替え・設定やプロジェクトの読み込みを行ったときに、欄の表示が選んだ表記へ整形されます。** 入力を確定しただけでは整形されないので、**打ち込んだ直後は打った形のまま残ります**（異常ではありません）。

### プロキシ設定

企業ネットワーク等でプロキシを経由して DEM タイルを取得する場合は、**設定 > プロキシ設定** からプロキシ URL を入力してください（例: `http://proxy.example.com:8080`）。OK を押すと即時反映されます（アプリの再起動は不要です）。空欄で OK を押すと OS のプロキシ設定に戻ります。

> プロキシが未設定で標高サーバーへ一切とどかない場合、計算は**十数秒で打ち切られ**、プロキシ設定を確認するようダイアログでお知らせします（地形が取れていないまま平坦な地形として完走することはありません）。

## 地図

![地図上に送信点・受信点と経路が表示された画面。地図をクリックして座標を拾える](images/shot_map.png)

ランチャー下部の **「地図」ボタン**を押すと、国土地理院の淡色地図を使った補助ウィンドウが開きます。地図はアプリ唯一のインスタンス（ランチャーが所有）で、上部の**モードセレクタ**で 4 つのモード（座標入力／連続追加／中継点／キャッシュ管理）を切り替えます。コアのシミュレーションは地図を開かなくても完結し、地図はあくまで便利機能です。

> 開いたとき、設定中の TX/RX の経路長に合わせて自動でズーム・センタリングします。

### 座標入力モード（既定）

地図をクリックすると **TX → RX** を交互に指定し、ランチャーの座標欄（開始/終了）へ自動で書き戻します（数値欄が常に正となります）。クリックでいつでも置き直せます。

- TX=塗り / RX=白抜きのシアンのマーカーと、両点を結ぶ経路ライン・中点の距離ラベルを表示します。
- ドラッグは地図の移動です（座標は確定したクリックでのみ更新）。

### 連続追加モード

複数経路へ経路を地図から次々に積んでいくモードです。モードセレクタの **「複数経路へ連続追加」** を選ぶと複数経路ウィンドウが開き（前面化し）、地図で **TX → RX** のペアを置くたびに複数経路へ 1 行が自動追加され、次の入力へ自動リセットされます（複数経路側で「＋行を追加」を押す必要はありません）。

- 各行の RF（周波数・アンテナ利得・アンテナ高）は、**追加した時点のランチャー値で凍結**されます。あらかじめランチャーで条件を決めてから積んでいく流れです。
- 複数経路にある全経路を地図上に表示します。確定した経路は **座標入力モードと同じ描き方**（TX=塗り / RX=白抜きのマーカー＋経路ライン＋中点の距離ラベル）で示します。ラベルには経路 ID が添えられるので、複数経路の表のどの行かが分かります。⚠️ **TX と RX がほぼ同じ位置にある経路では、2 つのマーカーが重なって見分けられません**（そういう経路は中継経路ウィンドウで扱ってください）。
- 複数経路側の行変更（削除・全クリア・CSV インポート・追加・複製・座標セルの編集確定）は地図の表示へリアルタイムに反映されます。
- 複数経路ウィンドウを閉じると、地図は座標入力モードへ戻ります。

### キャッシュ管理モード

DEM タイルのキャッシュ状況を確認し、任意エリアを事前取得（プリフェッチ）・削除できます。出張先や電波の弱い現場へ行く前に、必要範囲をオフライン用に取得しておく用途です。通常のシミュレーションでも経路周辺のタイルは自動でキャッシュされるため、**この画面を開かなくても支障はありません**。

**カバレッジ表示（自動）** — 地図を移動・拡大縮小すると、キャッシュ済み領域が半透明の色で常時表示されます。色は取得済みの最高精度です。

| 色     | 精度                       |
| ------ | -------------------------- |
| 緑     | 5m メッシュ（航空レーザ測量由来）|
| 黄     | 5m メッシュ（写真測量由来）|
| 水色   | 10m メッシュ               |

色が付いていない範囲は未取得です。

**操作（マウスジェスチャ）**

| 操作                          | 動作                               |
| ----------------------------- | ---------------------------------- |
| ドラッグ                      | 地図を移動                         |
| Ctrl + ドラッグ               | 範囲を選択してダウンロード         |
| Ctrl + Alt + ドラッグ         | 範囲を強制再取得（既存分も再 DL）  |
| Shift + Ctrl + ドラッグ       | 範囲のキャッシュを削除             |

ダウンロード・削除の前には対象エリア数や容量の目安を示す確認ダイアログが表示されます。進捗と結果はウィンドウ下部のステータスバーに表示されます。全キャッシュの削除は **設定 > 全キャッシュ削除** から行えます。

> **外部サーバーへの配慮**: タイルは国土地理院の公共サーバーから取得します。一度取得したタイルは再ダウンロードしません。広域の強制再取得は必要なときだけ行ってください。

## 使い方 — 個別シミュレーション

![地形断面グラフ。送受信点を結ぶ見通し線とフレネル第 1 ゾーンが地形に重ねて描かれ、遮蔽区間と受信レベル・マージンが表示されている](images/shot_profile.png)

### 1. ランチャーウィンドウ

起動すると入力フォームが表示されます。

#### サイト情報

| フィールド             | 説明                                          |
| ---------------------- | --------------------------------------------- |
| 開始座標（緯度, 経度） | TX 局の緯度・経度（例:`34.5429, 132.4118`） |
| 終了座標（緯度, 経度） | RX 局の緯度・経度                             |
| 送信アンテナ高（m）    | TX アンテナの地上高                           |
| 受信アンテナ高（m）    | RX アンテナの地上高                           |

#### 無線設定

| フィールド                     | 説明                       |
| ------------------------------ | -------------------------- |
| 周波数（MHz）                  | 周波数（1〜100,000 MHz）   |
| 送信電力（dBm）                | 送信電力                   |
| 送信 / 受信アンテナ利得（dBi） | アンテナ利得               |
| 受信感度（dBm）                | 受信感度（最小受信レベル） |

#### 伝搬環境

| フィールド            | 説明                                       |
| --------------------- | ------------------------------------------ |
| 環境区分              | 市街地 / 郊外 / 農村 / 見通し の 4 区分   |
| 植生高（m）           | 樹木・建物等の平均高さ                     |
| ライスKファクター（初期値） | 見通し/散乱電力比の初期値。表示用のみで計算には影響しない（デフォルト = 10.0） |
| 地形サンプル数        | 10〜2000（多いほど精度向上・取得時間増加） |

#### 案件情報（任意）

| フィールド | 説明                                                         |
| ---------- | ------------------------------------------------------------ |
| 案件名     | レポートのヘッダに載る案件名（個別・一括どちらのレポートにも反映） |
| メモ       | 自由メモ。**個別シミュレーションのレポートと、一括のサマリー頁**（`summary.html` / `report_all.html`）に載る。**一括の経路ごとのレポートには載らない**（サーベイ全体に掛かる情報なので経路ごとに繰り返さない） |

> 案件情報は **ランチャーが入力の源**です。ここで入力した値を、個別シミュレーションの保存レポートも、複数経路も踏襲します。複数経路側では読み取り専用（🔒）で表示され、「↻ ランチャーから更新」で取り込みます。

### 2. 「実行」ボタン（個別シミュレーション）

ボタンを押すと 2 段階でデータを取得します。

1. **DEMタイル事前取得**: TX/RX 間のバウンディングボックス内の全タイルをディスクキャッシュに保存します（最大 8 並列）。キャッシュ済みタイルはスキップされるため 2 回目以降は即完了します。
2. **標高データ取得**: サンプル点ごとに標高を並列取得します（最大 8 並列）。同じ TX/RX 座標・サンプル数であれば前回のキャッシュを即時使用します。

### 3. グラフウィンドウ

取得完了後、地形断面グラフが表示されます。

#### グラフの見方

| 表示要素   | 説明                      |
| ---------- | ------------------------- |
| 茶色の塗り | 地形（地球曲率補正済み）  |
| 緑色の塗り | 植生層（地表高 + 植生高） |
| 赤の破線   | 見通し線（LoS）           |
| シアンの帯 | 第 1 Fresnel ゾーン       |
| 黒の縦棒   | TX / RX アンテナ          |

#### スライダー

| スライダー     | 範囲        | 説明                            |
| -------------- | ----------- | ------------------------------- |
| 送信アンテナ高 | 0〜150 m    | TX アンテナ高をリアルタイム変更 |
| 受信アンテナ高 | 0〜150 m    | RX アンテナ高をリアルタイム変更 |
| 降雨量         | 0〜100 mm/h | 降雨強度をリアルタイム変更      |

スライダーを動かすと 50ms のデバウンス後に自動再計算されます。

#### 保存ボタン

現在の表示状態を `results/YYYYMMDD_HHMMSS/` に保存します（→ [保存パッケージ](#保存パッケージ)）。

### 4. 入力値の自動保存

個別シミュレーションを実行すると、そのときの入力値が `radiosim_conf.json` へ自動保存され、次の起動時に復元されます。**明示的に保存する操作は要りません。**

過去の条件をファイルから取り込みたい場合や、入力一式をまとめて持ち運びたい場合は、[ファイルメニュー](#ファイル)（**パラメータ読込** / **プロジェクトを保存・開く**）を使います。

## 使い方 — 複数経路

![複数経路の入力表。1 行 1 経路で、実行後の判定（OK / NG）と水平距離が各行に返っている](images/shot_batch.png)

ランチャーの **複数経路** ボタンで専用ウィンドウを開きます。

### 設計思想 — シングルで詰め、複数経路で確定する

**シングル（ランチャー）＝条件を詰める場／複数経路＝確定した条件で成果物を作る場**です。ランチャーが唯一の「真実の源」で、複数経路の各行は **行を追加した時点のランチャー欄をコピーして凍結した確定リンク** になります。

### 入力方法

**手動入力**: テーブルに直接 ID・座標・アンテナ高・周波数・送受信利得を入力します。行の追加・削除・ドラッグ並べ替え・セルの直接編集ができます。

表の右端の **水平距離(m)** 列は TX/RX 座標から自動計算される読み取り専用の表示です（座標を確定するたびに更新）。座標の打ち間違いは距離が極端な値になって現れるため、実行前に気づく手がかりになります。

- **＋行を追加**: その時点のランチャー欄（座標・周波数・利得・アンテナ高）をコピーして凍結した行を追加します。
- **地図から選択**: 地図を「複数経路へ連続追加」モードで開きます。地図で **TX → RX** のペアを置くたびに 1 行が自動で足されます（このウィンドウから地図を開けるようになったのは 2.7 からで、それまでは地図の側からしか始められませんでした）。
- **行を右クリック**: 行ごとのメニューが開きます。
  - **→ シングルへ送る**: その行の座標＋RF をランチャーへ読み込み、調整できます。
  - **⟳ RF をランチャーで更新**: ランチャーの現在の RF をその行へ書き戻します（**座標は保持**）。
  - 複製 / 削除。

**CSV インポート**: テンプレートボタンでサンプル CSV を保存し、編集後にインポートします。

#### CSV フォーマット

必須列: `id, start, end, h_tx, h_rx`

省略可能列: `freq, gain_tx, gain_rx, note`

```csv
id,start,end,h_tx,h_rx,freq,gain_tx,gain_rx,note
path01,"34.54, 132.41","34.53, 132.40",30.0,10.0,2400,12.5,8.0,メイン回線
path02,"34.55, 132.42","34.52, 132.39",20.0,15.0,,,,サブ回線
```

- `start` / `end` は「緯度, 経度」の形式でダブルクォートで囲んでください
- `freq` / `gain_tx` / `gain_rx` を省略した場合は共通設定の値が使われます（**経路ごとに変えられるリンク識別属性**です）。環境区分・降雨強度・回折モデルは共通設定で一括指定します
- `gain_tx` / `gain_rx` 列のない旧 CSV もそのまま読めます（後方互換・利得は共通設定を継承）
- 列名は**大小文字と前後の空白を区別しません**（`ID,Start,…` でも読めます）。`id` は**大小文字を区別せず**一意である必要があります（`p01` と `P01` は同じ出力フォルダになるため重複として弾かれます）

### 共通設定（ランチャーのスナップショット）

ウィンドウ上部の **共通設定** は、経路ごとの個別設定が指定されていない場合に使われるデフォルト値です。**読み取り専用**で、ランチャー（真実の源）のスナップショットとして表示されます。**↻ ランチャーから更新** ボタンでランチャーの現在値を取り込めます。

### 実行と結果

**実行** ボタンを押すと経路を順次処理します。処理中は進捗（処理済み / 全体）が帯に出て、**判定は終わった経路の行へ返ります**。

完了後、`results/batch_YYYYMMDD_HHMMSS/` に以下が保存されます。

| ファイル                     | 内容                                               |
| ---------------------------- | -------------------------------------------------- |
| `summary.html`             | 全経路のサマリーレポート（グラフのサムネイル付き） |
| `summary.csv`              | 全経路の数値結果（スプレッドシートで開けます・距離は m）|
| `summary.kml`              | OK / NG / エラーを色分けした Google Earth 用 KML   |
| `report_all.html`          | サマリ＋全経路を 1 文書へ連結（Ctrl+P 一発で全ページ分の PDF）|
| `{id}/report.html`         | 経路ごとの詳細レポート（地形断面グラフ＋経路地図を埋め込み）|
| `{id}/profile.png`         | 地形断面グラフ                                     |
| `{id}/path.kml`            | 地形・LoS・Fresnel ゾーン・遮蔽区間の 3D KML       |
| `{id}/settings.json`       | 経路ごとの入力パラメータ                           |
| `{id}/terrain_profile.csv` | 地形断面データ                                     |
| `{id}/report.txt`          | テキスト形式のリンクバジェットレポート             |

## 使い方 — 条件探索（比較 / スイープ）

![条件探索の比較画面。1 本の経路に対し周波数と利得を変えた 4 条件の受信レベルとマージンが並び、最後の条件だけ NG になっている](images/shot_scenario.png)

**1 本の確定した経路を、条件を変えて掘る**ための画面です。ランチャーの「条件探索」ボタンで開きます。経路（座標）とサンプル数はランチャーの値に固定され、**地形データの取得は 1 回だけ**で、そのうえで条件を N 通り計算します（同じ経路で何度も回しても DEM の再取得は起きません）。

上部のトグルで 2 つのモードを切り替えます。ランチャー側で座標やパラメータを変えたときは、右上の **「↻ ランチャーから更新」** で取り込み直してください（**押すまで画面の値のまま計算します**＝画面と計算がずれません）。

### 比較（ベース＋条件 N）

- 左端の **ベース**列はランチャーの現在値（読み取り専用）＝**基準は動かしません**。
- **条件 1 … 条件 5** の列に、変えたい欄だけ書き換えます（初期値はベースと同じ）。「＋ 条件を追加」で最大 5 列まで増やせます。
- 変えられるのは周波数・送信電力・送受信アンテナ利得・受信感度・送受信アンテナ高・植生高・降雨強度・環境・回折モデルです。**座標とサンプル数は変えられません**（経路そのものの比較は複数経路の仕事）。
- レポートは項目を縦に並べた差分表で、**ベースとの差をセル内に併記**します（例 `-76.44 (+13.56)`）。差が出た行は地の色が変わります。

### スイープ（1 軸 N 点）

- **軸**（アンテナ高・周波数・降雨強度など）と範囲・**点数**（2〜41 点）を指定します。
- 範囲の指定は 2 通りから選べます。**開始 / 終了**（絶対値で指定）と、**ベース ±**（今の値を中心に前後へ振る）。**ベース ±** は「今の 30m から ±10m で見たい」という考え方をそのまま入れられます。切り替えても振り幅は引き継ぎ、内部では常に開始/終了へ直してから計算します（プロジェクトファイルにも開始/終了で保存されます）。
- レポートは**折れ線＋数値表**です。折れ線には判定のしきい値（マージン 0 dB）が引かれ、点は判定で塗り分けられます（OK＝緑 / NG＝橙）。色の変わり目が「アンテナ高を何 m にすれば足りるか」です。点数を最大（41 点）にしても **A4 縦 1 枚**に収まります（表は 1 列のまま、行を詰めて収めます＝上から下へ変化を追えます）。
- マージンの振れ幅が大きいとき（深く塞がれた経路を含むとき）は縦軸を対数寄りに切り替えて、しきい値付近が潰れないようにしています。

### 実行と結果

**実行**を押すと、地形取得 → 条件計算 → レポート生成の順に進み、進捗バーが最後まで伸びます。完了すると保存先を告げるダイアログが出て、そのままレポートを開けます（個別・一括と同じ流儀）。あとから見るときはランチャーの「結果フォルダ」から開いてください。

`results/scenario_YYYYMMDD_HHMMSS/` に以下が保存されます。

| ファイル          | 内容                                                     |
| ----------------- | -------------------------------------------------------- |
| `scenario.html` | A4 縦 1 枚のレポート（比較＝差分表 / スイープ＝折れ線＋表）|
| `scenario.csv`  | 全条件・全点の数値（スプレッドシートで開けます）           |

## 使い方 — 中継経路

![中継経路の画面。送信点・中継点・受信点の 3 地点と、区間ごとの受信レベル・マージン・判定が表に返っている](images/shot_multihop.png)

**1 本の回線を中継点で継ぐ**ときの画面です。ランチャーの **中継経路** ボタンで開きます。山を挟んで直接は届かない 2 点を、見通しの利く尾根などに中継点を置いて繋ぐ検討に使います。

### 前提 — 再生中継（受けて送り直す）

中継点で**いったん受信し、あらためて送信する**方式（再生中継）を前提にしています。したがって:

- 区間ごとに独立したリンクバジェットを計算します（**区間の損失は足し合わせません**）。
- **全体の可否は、一番余裕の少ない区間**で決まります。レポートには全体判定と**区間ごとの内訳の両方**を載せます（どこが苦しいかが分からないと、中継点を足すのかアンテナを上げるのかを決められないため）。
- **反射板（パッシブリフレクタ）による中継は対象外**です。損失の連なり方が別物で、このツールの計算には入っていません。

### 地点と区間

- **地点の表**が入力面です。**先頭が送信点・末尾が受信点**で固定され、「地点を追加」で足した点は**その手前に中継点として挿さります**（並びがそのまま経路の順序です）。役割（送信 / 中継 / 受信）は行に表示されます。
- **行の `＋` を押すと、その行の下に中継点が挿さります**——間に 1 点足したいときに、後ろの地点を消して打ち直す必要はありません。受信点の行に `＋` が出ないのは、末尾が受信点で固定だからです。⚠️ **地点の名前は振り直しません**（`R1` を「東の丘」に直した入力を上書きしないため）。並びは行の順序と役割の表示が示します。
- 地点ごとに **座標**と**アンテナ高**を入力します。**中継点の行には `×` が付き、任意の地点だけを消せます**（送信点・受信点は消せないので `×` は出ません）。中継点を消すと、その地点から出ていく区間の設定も一緒に消えます。**挿したときは逆に、その地点から出ていく区間が空欄で増えます**（同じ位置で挿して消せば元どおりです）。
- 座標は**十進度でも度分秒でも入力できます**。入力を確定すると、設定（設定 > 座標の表示形式）の表記へ整形されます。**高さは地点にだけあります**——中継点のアンテナは 1 本なので、「前の区間の受信高」と「次の区間の送信高」に別々の値を入れられないようにしてあります。
- **区間の表**では、区間ごとに **周波数・送信利得・受信利得**を上書きできます（空欄なら共通設定＝ランチャーの値を使います）。中継点で送受のアンテナが別物になるケースを表現するためです。
- **地図から選択**を押すと地図が中継点モードになり、クリックした順に地点へ座標が入ります。地図には地点を順に結ぶ折れ線が引かれ、**区間ごとの水平距離**が線の中点に表示されます（区間の表には距離の列が無いので、区間がどれくらいの長さかはここで読めます）。
- 送信点・受信点の座標は、**ウィンドウを開いた時点のランチャーの値**が初期値として入ります（中継点は空のまま）。
- 中継点は最大 7 つ（区間は最大 8 つ）です。

> **⚠️ 中継点は「置く」もので「動かして探る」ものではありません。** 1 区間ごとに標高データを取りに行くため、動かすたびに新しい取得が走ります。高さや条件を振って探るのは[条件探索](#使い方--条件探索比較--スイープ)の役目です。

### 実行と結果

**実行**を押すと区間を順に処理し、区間ごとの結果（受信レベル・マージン・判定）が一覧に積み上がります。完了すると全体判定（一番苦しい区間の値）が表示されます。

`results/multihop_YYYYMMDD_HHMMSS/` に以下が保存されます。

| ファイル              | 内容                                    |
| ----------------- | ------------------------------------- |
| `route.html`      | 経路全体の合成シート（全体判定＋区間別の内訳＋俯瞰地図）          |
| `report_all.html` | 合成シート＋全区間の詳細を 1 文書へ連結（Ctrl+P で一括 PDF） |
| `hops.csv`        | 区間別の数値（1 行 = 1 区間・スプレッドシートで開けます）      |
| `{id}/`           | 区間ごとのパッケージ（個別シミュレーションと同じ構成）           |

## プロジェクトファイル（.rsproj）

**入力一式を 1 つのファイルに束ねて**保存し、あとで続きから再開するための仕組みです。メニューの **ファイル → プロジェクトを保存 / プロジェクトを開く** から使います。

### 束ねるもの・束ねないもの

| 含む                        | 含まない                          |
| ------------------------- | ----------------------------- |
| 座標・全パラメータ（ランチャーの入力一式）     | **計算結果**（結果は `results/` 側の仕事） |
| 案件情報（案件名・自由メモ）            | **アプリ設定**（テーマ・言語・プロキシ）        |
| 複数経路の行              | ウィンドウの位置・大きさ・開閉状態             |
| 条件探索の条件（比較の列 / スイープの軸と範囲） |                               |
| 中継経路の地点と区間                |                               |

**テーマ・言語・プロキシを含めないのは意図的です**——他人から受け取ったプロジェクトを開いた瞬間に、表示言語やネットワーク設定が変わってしまわないようにしています。

### 保存するとき

- 開いているウィンドウ（一括 / 条件探索 / 中継経路）からは**そのときの値**が保存されます。
- **閉じたウィンドウの内容も保存されます**（前回の値を持ち越します）。一括のウィンドウを閉じてから保存しても、行は消えません。
- 数値として読めない値が入っている部分は保存せず、その旨をダイアログでお知らせします（壊れたファイルを黙って作らないため）。

### 開くとき

- **開いているウィンドウは閉じません**。上に「プロジェクトを読み込みました。このウィンドウの内容を差し替えられます。」の帯が出るので、**「内容を取り込む」を押したときだけ**そのウィンドウの内容が入れ替わります（押さなければ画面は変わりません）。帯は `×` で閉じられます。
- ランチャーの入力欄と案件情報はその場で入れ替わります。
- **閉じているウィンドウの内容は、そのウィンドウを開いたときに反映されます**（このアプリは「ウィンドウを開いた時点の値で固定する」流儀なので、それに合わせています）。
- 取り込まないままウィンドウを閉じた場合は、**画面に見えていた内容のほうが残ります**（次に保存すると、そちらが書き出されます）。
- 新しい版の RadioSim で保存されたファイルは開けません（黙って壊さないため、その旨を表示します）。

## 計算モデル詳細

### 地球曲率補正

実際の電波伝搬では大気の屈折により電波は地球の曲率より大きく曲がります。これを等価地球半径係数 K でモデル化します。本ツールでは標準大気（K = 4/3 ≈ 1.333）を内部固定値として使用します。

```
等価地球半径 Re = R_earth × K  （K = 4/3 固定）
曲率補正量 Δh(d) = d × (D - d) / (2 × Re)  [m]
```

| K の値       | 意味                                 |
| ------------ | ------------------------------------ |
| 4/3 ≈ 1.333 | 標準大気（本ツール使用値・固定）     |
| K > 4/3      | 大気ダクト（電波がより大きく曲がる） |
| K < 4/3      | 負の屈折（電波が地面側に曲がる）     |

### Fresnel ゾーン

電波は幾何光学的な直線だけでなく、その周囲の楕円体状の領域（Fresnel ゾーン）を伝搬します。第 1 Fresnel ゾーンが地形・植生に遮蔽されると回折損が発生します。

```
r₁(d) = √(λ × d₁ × d₂ / (d₁ + d₂))
```

### 回折損

#### Deygout 法（デフォルト・**独自実装**）

多重回折に対応した再帰的モデルです。最大遮蔽点を主障害物として区間を分割し、損失を再帰的に加算します。

⚠️ **「ITU-R P.526 準拠」とは名乗りません**（2026-08-09 に表記を訂正）。本実装が P.526 から使っているのは**ナイフエッジ回折損の式 J(ν) だけ**で、現行 P.526-16 が複数障害物に定める**孤立円筒モデル**も、一般地形の**Bullington 法**も、標準の**補正項**も持ちません。⇒ **広がりのある障害物では過大評価します**（既知の欠陥・上の「既知の制限」を参照）。

#### Fresnel-Kirchhoff 損失 J(ν)

```
J(ν) = 6.9 + 20 × log₁₀(√((ν - 0.1)² + 1) + ν - 0.1)  [dB]  （ν > -0.8）
J(ν) = 0                                                          （ν ≤ -0.8）
```

#### Single 法

全サンプル点の ν を計算し、最大値のみで J(ν) を算出するシンプルなモデルです。

### 植生減衰

LoS 線が植生頂点に侵入した深さから経験的に推定します。

```
侵入深さ(d)   = max(0, veg_top(d) - LoS(d))
重み(d)       = clip(侵入深さ / r₁(d), 0, 1)
有効植生長    = Σ[重み(d)] × サンプル間隔
Veg Loss      = min(有効植生長 × coeff, 45 dB)
```

| 周波数帯   | coeff         |
| ---------- | ------------- |
| 1 GHz 未満 | 0.12 × f^0.5 |
| 1〜6 GHz   | 0.20 × f^0.7 |
| 6 GHz 超   | 0.35 × f^0.9 |

### 環境損失

地形・植生損失では捉えきれないマルチパス・散乱等を経験的に補正します。

```
Env Loss = base + blocked_ratio × blk_c + slant_dist × dist_c + diff_loss × diff_c
```

| 環境区分 | base | blk_c | dist_c | diff_c | min | max  |
| -------- | ---- | ----- | ------ | ------ | --- | ---- |
| 市街地   | 10.0 | 0.08  | 1.20   | 0.15   | 6.0 | 30.0 |
| 郊外     | 6.0  | 0.05  | 0.80   | 0.10   | 3.0 | 30.0 |
| 農村     | 4.0  | 0.03  | 0.50   | 0.08   | 2.0 | 25.0 |
| 見通し   | 2.0  | 0.01  | 0.30   | 0.05   | 1.0 | 15.0 |

### 降雨減衰（ITU-R P.838-3）

```
γ_R = k × R^α  [dB/km]
Rain Loss = γ_R × d_slant
```

2.4 GHz では降雨の影響は非常に小さく（100 mm/h で約 0.1 dB/km 程度）、実用的な影響が出るのはおおむね 10 GHz 以上からです。

### 大気減衰（ITU-R P.676-13 Annex 2 簡易式）

```
γ_total = γ_O₂ + γ_H₂O  [dB/km]
Gas Loss = γ_total × d_slant
```

### リンクバジェット

```
EIRP      = P_tx + G_tx                             [dBm]
FSPL      = 20×log₁₀(d) + 20×log₁₀(f) - 147.55   [dB]
Total Loss = FSPL + Diff + Veg + Env + Rain + Gas   [dB]
P_rx      = EIRP + G_rx - Total Loss                [dBm]
Act Margin = P_rx - Sensitivity                     [dB]
Status    = OK（≥ 0 dB）/ NG（< 0 dB）
```

## 既知の制限・注意事項

### 精度

- DEM の水平解像度（5〜10m）が伝搬計算精度の上限です。建物単体の遮蔽は考慮されません
- Deygout 法は多重回折の近似であり、**発散していない経路では**±5〜15 dB 程度の誤差があります（**発散する経路にはこの範囲は当てはまりません**）
- 🔴 **回折損（既定の Deygout 法）が過大に出ることがあり、どの経路で信頼できるかを事前に見分ける方法がありません**（既知の欠陥・修正予定）。尾根のような**広がりのある障害物**を多数の独立した稜線として数えてしまうため、山越えでは**数百〜数千 dB** になります。⚠️ **起伏の大きさでも F1 遮蔽率でも判定できません**＝起伏 25m の滑らかな丘（10km・150MHz）で、Single 法 **0.0 dB** に対し Deygout 法は **65 dB** を返します（F1 遮蔽率は 100% 未満のまま）。**同じ起伏でも地形の形しだいで 10 倍以上変わります**（細い峰なら同条件で 5.7 dB）。⚠️ **F1 遮蔽率は画面・レポート・CSV とも 100% で頭打ち**（内部の生値は 100% を超えます）なので、率の側からは異常に気づけません。
- 🛡 **上の欠陥に対して今できる自衛策**＝**「回折モデル」を `Single` に切り替えてもう一度計算し、2 つの値を見比べてください。**大きく食い違う経路では、**既定（Deygout）の値を信用しないでください**——判定が NG でも、**その NG が正しいかどうかはこの値からは分かりません**。⚠️ **これは「どちらが正しいか」を決める手段ではありません**＝2 つの差が大きければ**結果がモデルの選び方に強く依存している**と分かる、という診断です。**差が小さくても正しさは保証されません**（どちらの値も実測や基準実装と突き合わせていないため）。⚠️ `Single` 法は**複数障害物の合成損失を表現しない**（最大の 1 点しか見ない）ので、**Deygout より小さく出ることがあります**。⚠️ これも**真の値との関係は分かりません**（「Single 側が安全寄り」という意味ではありません）
- 植生減衰モデルは経験的近似です。樹種・密度・季節変動は考慮されません
- 環境損失係数は経験値であり、特定地域・用途への適合は保証されません

### データカバレッジ

- **本ツールのDEMは日本国内限定です。** 国土地理院タイルは日本国外をカバーしないため、日本国外の座標を入力すると標高 0m が返ります
- `dem5a_png` / `dem5b_png`（5m）は全国カバーではありません。未整備地域は自動的に `dem_png`（10m）にフォールバックします
- 海上・湖沼・データ欠損箇所は標高 0m として扱います

### 距離

- 実用上は 20 km 以内を推奨します。それを超える距離はスクリーニング用途の精度限界を超えます

### 操作

- グラフウィンドウを開いている間は同じルートのパラメータ変更ができません
- 地形キャッシュはアプリ再起動でリセットされます（ディスクキャッシュはセッションをまたいで有効です）
