# スクリーンショットの撮り方（README 用）

README に載せる画面を**同じ構図で撮り直せる**ようにするための手順書。
版が変わっても、ここに書いた座標・条件のまま撮れば差し替えが 1 往復で済む。

**なぜ手順書が要るか**＝スクショは実在の地点が公開される資産で、毎回ちがう座標で
撮ると ①どこの回線か分からない絵が増える ②版ごとに構図が変わって差分が読めない、
の 2 つが起きる。⇒ **定番ペアを決めて使い回す。**

## ⚠️ 先に読む — 撮れる経路には制約がある（2026-08-08 実測）

**起伏のある経路（山越え）は、今のバージョンでは撮ってはいけない。**
回折損が発散し、**回折 1000〜2400 dB・F1 遮蔽率 400〜2200%** という値が画面に出る
（既知の未修正バグ＝Deygout の再帰が広がりのある障害物で発散する／遮蔽率が 100% を
超える。どちらも 3.2 で直す予定）。README の先頭に置く絵がこれでは、**製品の顔として
最初に見えるのが未修正の欠陥**になる。

実測（すべて 150MHz・5W・アンテナ 40/20m・植生 0m）:

| 経路 | 距離 | 起伏 | 回折損 | F1 遮蔽率 | 判定 |
|---|---|---|---|---|---|
| 県庁 → 安佐南区役所 | 6.8km | 10m | 0.9 dB | 54.5% | OK |
| **県庁 → 海田町役場** | **7.4km** | **25m** | **11.2 dB** | **97.4%** | **OK** |
| 県庁 → 廿日市市役所 | 12.9km | 21m | 6.6 dB | 90.9% | OK |
| 呉市役所 → 江田島市役所 | 10.8km | 132m | **437 dB** | **258%** | NG |
| 安佐南区役所 → 安佐北区役所 | 8.1km | 518m | **1861 dB** | **851%** | NG |
| 県庁 → 東広島市役所 | 26.3km | 575m | **2409 dB** | **1687%** | NG |

⇒ **健全に計算できるのは起伏 25m 程度までの平地・沿岸の経路**。
下の定番ペアはその中から「**F1 が地形に食い込み、回折損が乗り、それでもリンクは成立する**」
＝教材として一番よく効く 1 本を選んである（遮蔽 97.4% で OK）。

## いつ撮るか（2026-08-08 ユーザー決定）

**RC1 の実機確認と同時に撮る。最終 RC では撮り直さず「照合」だけ。**

- **なぜ alpha では撮らないか**＝b / RC で欠陥修正が入り、窓の見た目が動きうる。
  2.7 は UI のスライスが全部完了して**見た目の変更は打ち止め**だが、確率は 0 ではない
  （スライス C は実機確認から修正が 1 件入った）。
- **なぜ「最終 RC でまとめて」にしないか**＝⛔ **画像は最後のビルドより前に無いと配布物に入らない**。
  `radiosim.spec` が `README_binary_ja/en.md` を同梱し、そこへは base64 で埋め込むので、
  **ビルド後に撮ると同梱 README だけ画像なしで出る**（2.3RC1 で実際に踏んだ形）。
  加えて、リリース工程という一番忙しい瞬間に手作業の撮影を積むと飛ぶ——**飛んだ実績がある**。
- **だから**：撮影は **RC1 の実機確認のついで**（窓を 1 つずつ開く作業を既にやっているので追加コストはほぼゼロ）。
  最終 RC では **`tools/qa-hook/release-checklist.txt` の 1 行**で画面と見比べ、**動いていたときだけ撮り直す**。

⚠️ **版番号が写るのはランチャーだけ**（`root.title(version.APP_FULL)`）。下の 3 枚は
グラフ窓＝`150.0 MHz` / 地図・複数経路＝i18n のタイトルなので**版は写らない**。
⇒ **ランチャーを撮り足すなら、そのときだけ「版が確定してから」の制約が付く。**

## 撮影環境

**実機（1920×1080 / 100%）で撮る。** 開発機（WQHD）で撮ると窓が実機より大きく写り、
利用者が実際に見る絵と食い違う（窓の高さ予算は実機 990px が上限）。

- テーマ：**ライト**（既定・印刷や資料に貼ったときに読みやすい）
- 表示言語：**日本語**（英語版 README にも同じ画像を使う＝撮り直しは維持コストに見合わない）
- 座標の表示形式：**DD（十進度）**
- 撮る範囲：**窓 1 つぶん**（デスクトップ全体ではなく対象の窓だけ）。
  対象の窓を前面にして <kbd>Alt</kbd>+<kbd>PrintScreen</kbd>。

| 項目 | 値 |
|---|---|
| 送信点 (TX) | 広島県庁 `34.3966, 132.4596` |
| 受信点 (RX) | 海田町役場 `34.3714, 132.5347` |
| 送信アンテナ高 | **40** m |
| 受信アンテナ高 | **20** m |
| 周波数 | **150** MHz |

| 送信 / 受信利得 | **6** / **6** dBi |
| 受信感度 | −85 dBm（既定のまま） |
| 植生高 | **0** m |
| 環境区分 / 降雨強度 / 回折モデル / サンプル数 | 見通し / 0 / Deygout / 200（すべて既定のまま） |

**この条件での結果**（実測・撮る前の答え合わせに使う）＝ **判定 OK・マージン +23.6 dB・

- ⚠️ **緯度経度は施設のおよその位置**（地図でクリックした値でよい）。撮影時に拾い直したら

## 撮る画面（3 枚）

### 1 枚目 — 地形断面（`docs/images/shot_profile.png`）

**主役の絵。** ランチャーに上表の値を入れ、**個別シミュレーション**を実行してグラフウィンドウを撮る。

- 写っていること＝地形断面・見通し線・**フレネル第 1 ゾーン**・遮蔽区間・受信レベル・マージン・判定。
- スライダー（アンテナ高・降雨強度）は**触らない**（表の値のまま写す）。
- alt：`地形断面グラフ。送受信点を結ぶ見通し線とフレネル第 1 ゾーンが地形に重ねて描かれ、遮蔽区間と受信レベル・マージンが表示されている`

### 2 枚目 — 地図（`docs/images/shot_map.png`）

ランチャーの **地図** ボタンで開き、上のペアが経路として引かれた状態（座標入力モード）を撮る。

- **経路の両端が画面に入り、地形の起伏が分かる倍率**にする。
- alt：`地図上に送信点・受信点と経路が表示された画面。地図をクリックして座標を拾える`

### 3 枚目 — 複数経路（`docs/images/shot_batch.png`）

ランチャーの **複数経路** ボタンで開き、**下の 4 行を実行し終えた状態**（判定列に OK / NG が出ている）を撮る。
共通設定は上表のまま（行ごとに変えるのは `freq` と、`hatsukaichi` の **利得だけ**）。

| id | start | end | h_tx | h_rx | freq | 利得 tx/rx | 期待される判定 |
|---|---|---|---|---|---|---|---|
| `asaminami` | `34.3966, 132.4596` | `34.4570, 132.4700` | 40 | 20 | 150 | 6 / 6 | **OK**（+35.9 dB） |
| `kaita` | `34.3966, 132.4596` | `34.3714, 132.5347` | 40 | 20 | 150 | 6 / 6 | **OK**（+23.6 dB） |
| `hatsukaichi` | `34.3966, 132.4596` | `34.3486, 132.3317` | 40 | 20 | 2400 | **0 / 0** | **NG**（−8.8 dB） |
| `asaminami24` | `34.3966, 132.4596` | `34.4570, 132.4700` | 40 | 20 | 2400 | 6 / 6 | **OK**（+13.2 dB） |

- **OK と NG が混ざった表**にするのが狙い（判定列は 2.7 で入った目玉）。
- 4 行とも遮蔽率 100% 以下＝**発散域に入らない**ことを実測で確認済み（`hatsukaichi` 63.7% / `kaita` 97.4% / `asaminami` 54.5% / `asaminami24` 0%）。
- 🔴 **NG は利得で作る。アンテナ高を下げて作ってはいけない**（2026-08-09 実測）。`hatsukaichi` の `h_rx` を 20 → 10m にすると NG にはなるが **F1 遮蔽率が 105%** になり、**画面に未修正の欠陥（遮蔽率が 100% を超える。上の「先に読む」と同じ既知バグ）が写る**。5m で 125.7%、`h` 20/10m で 135.0%。⇒ 利得 0 dBi なら遮蔽 63.7%・回折 1.86 dB のまま NG になり、話としても自然（利得の低いアンテナでは 12.9km を 2.4GHz で飛ばせない）。⚠️ **上の「撮れる経路の制約」と同じ型**＝*被写体の作り方*にも未修正バグの制約がかかる。
- ⚠️ **2400MHz の 2 行は、2026-08-09 まで実測ではなく外挿だった**（`hatsukaichi` −5.4 / `asaminami24` +8.2 と書いてあった）。150MHz の実測から `20log10(2400/150)=24.08 dB` を引いて求めたと見られるが、**実際には周波数を上げると環境損失は下がる**（−0.5 dB）ため、2 行とも 3.4〜3.6 dB ずれていた。⇒ **この表の値は必ず実測で埋める**（150MHz 側は当時から一致しており、ずれたのは測らずに書いた行だけ）。
- 行の中身（ID・座標・アンテナ高・判定）が**潰れずに読める**こと。
- alt：`複数経路の入力表。1 行 1 経路で、実行後の判定（OK / NG）と水平距離が各行に返っている`

保存先は `docs/images/`（未作成なら作る）。**PNG のまま・加工なし。**

## 撮ったあとの作業（Claude 側）

1. `docs/images/` へ 3 枚を置く。
2. `README.md` の冒頭（リード文の直後）へ 1 枚目、`## 主な機能` の近くへ 2・3 枚目。
3. `README_ja.md` / `README_en.md` は該当する「使い方」節の先頭へ。
4. `README_binary_ja.md` / `README_binary_en.md` は **base64 でインライン埋め込み**
   （同梱物は自己完結が方針。`logo.png` が同じ方式）。⚠️ **埋め込み後にファイルサイズを
   実測する**——跳ねるようなら幅を縮めるか枚数を減らす（リンク参照への退避は最後の手段）。
5. 4 本すべてで **alt を日本語**にする（可読性と検索面積の両取り）。
