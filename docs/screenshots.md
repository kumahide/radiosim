# スクリーンショットの撮り方（README 用）

README に載せる画面を**同じ構図で撮り直せる**ようにするための手順書。
版が変わっても、ここに書いた座標・条件のまま撮れば差し替えが 1 往復で済む。

**なぜ手順書が要るか**＝スクショは実在の地点が公開される資産で、毎回ちがう座標で
撮ると ①どこの回線か分からない絵が増える ②版ごとに構図が変わって差分が読めない、
の 2 つが起きる。⇒ **定番ペアを決めて使い回す。**

## ⚠️ 先に読む — 撮れる経路には制約がある（2026-08-08 実測）

**起伏のある経路（山越え）は、今のバージョンでは撮ってはいけない。**
回折損が発散し、**回折 1000〜2400 dB** という値が画面に出る（既知の未修正バグ＝
Deygout の再帰が広がりのある障害物で発散する。3.2 で直す予定）。README の
先頭に置く絵がこれでは、**製品の顔として最初に見えるのが未修正の欠陥**になる。

⚠️ **F1 遮蔽率の欄は下表と画面で意味が違う**＝下表は `models` の**生値**（上限なし）で、
**画面・レポート・CSV は `units` が 100% で頭打ちにする**（[units.py:86](../core/units.py#L86)）。
つまり**発散していても画面の率は「100.0%」に見える**＝率からは異常に気づけない。
撮影時は**回折損の dB のほうを見て**判断すること。

実測（すべて 150MHz・5W・アンテナ 40/20m・植生 0m）／**F1 遮蔽率は生値**:

| 経路 | 距離 | 起伏 | 回折損 | F1 遮蔽率（生値） | 判定 |
|---|---|---|---|---|---|
| 県庁 → 安佐南区役所 | 6.8km | 10m | 0.9 dB | 54.5% | OK |
| **県庁 → 海田町役場** | **7.4km** | **25m** | **11.2 dB** | **97.4%** | **OK** |
| 県庁 → 廿日市市役所 | 12.9km | 21m | 6.6 dB | 90.9% | OK |
| 呉市役所 → 江田島市役所 | 10.8km | 132m | **437 dB** | **258%** | NG |
| 安佐南区役所 → 安佐北区役所 | 8.1km | 518m | **1861 dB** | **851%** | NG |
| 県庁 → 東広島市役所 | 26.3km | 575m | **2409 dB** | **1687%** | NG |

⇒ **健全に計算できるのは起伏 25m 程度までの平地・沿岸の経路**。
下の定番ペアはその中から「**F1 が地形に食い込み、回折損が乗り、それでもリンクは成立する**」
＝教材として一番よく効く 1 本を選んである（遮蔽 97.4% で OK）。

## いつ撮るか（2026-08-08 ユーザー決定）

**RC1 の実機確認と同時に撮る。最終 RC では撮り直さず「照合」だけ。**

- **なぜ alpha では撮らないか**＝b / RC で欠陥修正が入り、窓の見た目が動きうる。
  2.7 は UI のスライスが全部完了して**見た目の変更は打ち止め**だが、確率は 0 ではない
  （スライス C は実機確認から修正が 1 件入った）。
- **なぜ「最終 RC でまとめて」にしないか**＝⛔ **画像は最後のビルドより前に無いと配布物に入らない**。
  `radiosim.spec` が `README_binary_ja/en.md` と**画像そのもの**を同梱するので、
  **ビルド後に撮ると同梱 README だけ画像なしで出る**（2.3RC1 で実際に踏んだ形）。
  加えて、リリース工程という一番忙しい瞬間に手作業の撮影を積むと飛ぶ——**飛んだ実績がある**。
- **だから**：撮影は **RC1 の実機確認のついで**（窓を 1 つずつ開く作業を既にやっているので追加コストはほぼゼロ）。
  最終 RC では **`tools/qa-hook/release-checklist.txt` の 1 行**で画面と見比べ、**動いていたときだけ撮り直す**。

⚠️ **版番号が写るのはランチャーだけ**（`root.title(version.APP_FULL)`）。下の 5 枚は
グラフ窓＝`150.0 MHz` / 地図・複数経路・条件探索・中継経路＝i18n のタイトルなので**版は写らない**。
🔴 **だからランチャーは撮らない**（2026-08-09 ユーザー確定）＝撮ると**リリースのたびに古い版が
README に残る**か毎版撮り直すかの二択になり、加工なしの方針ではトリミングでも逃げられない。
入力欄が並ぶだけで情報量も低い。
⇒ **ランチャーを撮り足すなら、そのときだけ「版が確定してから」の制約が付く。**

## 撮影環境

**実機（1920×1080 / 100%）で撮る。** 開発機（WQHD）で撮ると窓が実機より大きく写り、
利用者が実際に見る絵と食い違う（窓の高さ予算は実機 990px が上限）。

- テーマ：**ライト**（既定・印刷や資料に貼ったときに読みやすい）
- 表示言語：**日本語**（英語版 README にも同じ画像を使う＝撮り直しは維持コストに見合わない）
- 座標の表示形式：**DD（十進度）**
- 撮る範囲：**窓 1 つぶん**（デスクトップ全体ではなく対象の窓だけ）。
  対象の窓を前面にして <kbd>Alt</kbd>+<kbd>PrintScreen</kbd>。

### 3 枚目 — 複数経路（`docs/images/shot_batch.png`）

ランチャーの **複数経路** ボタンで開き、**下の 4 行を実行し終えた状態**（判定列に OK / NG が出ている）を撮る。
共通設定は上表のまま（行ごとに変えるのは `freq` と、`hatsukaichi` の **利得だけ**）。

| id | start | end | h_tx | h_rx | freq | 利得 tx/rx | 期待される判定 |
|---|---|---|---|---|---|---|---|
| `asaminami` | `34.3966, 132.4596` | `34.4570, 132.4700` | 40 | 20 | 150 | 6 / 6 | **OK**（+35.9 dB） |
| `kaita` | `34.3966, 132.4596` | `34.3714, 132.5347` | 40 | 20 | 150 | 6 / 6 | **OK**（+23.6 dB） |
| `hatsukaichi` | `34.3966, 132.4596` | `34.3486, 132.3317` | 40 | 20 | 2400 | **0 / 0** | **NG**（−8.8 dB） |
| `asa2400` | `34.3966, 132.4596` | `34.4570, 132.4700` | 40 | 20 | 2400 | 6 / 6 | **OK**（+13.2 dB） |

- **OK と NG が混ざった表**にするのが狙い（判定列は 2.7 で入った目玉）。
- 4 行とも遮蔽率の生値が 100% 以下＝**発散域に入らない**ことを実測で確認済み（`hatsukaichi` 63.7% / `kaita` 97.4% / `asaminami` 54.5% / `asaminami24` 0%）。
- 🔴 **NG は利得で作る。アンテナ高を下げて作ってはいけない**（2026-08-09 実測）。`hatsukaichi` の `h_rx` を 20 → 10m にすると NG にはなるが **F1 遮蔽率の生値が 105%** になる（5m で 125.7%、`h` 20/10m で 135.0%）＝**発散域の入口に踏み込んだ絵**になる。⚠️ **画面には「100.0%」と写る**（`units` の頭打ち）ので**絵からは異常が見えない**が、それは欠陥が無いという意味ではなく**隠れているだけ**で、回折損の側に出る。⇒ 利得 0 dBi なら遮蔽 63.7%・回折 1.86 dB のまま NG になり、話としても自然（利得の低いアンテナでは 12.9km を 2.4GHz で飛ばせない）。⚠️ **上の「撮れる経路の制約」と同じ型**＝*被写体の作り方*にも未修正バグの制約がかかる。
- ⚠️ **2400MHz の 2 行は、2026-08-09 まで実測ではなく外挿だった**（`hatsukaichi` −5.4 / `asaminami24` +8.2 と書いてあった）。150MHz の実測から `20log10(2400/150)=24.08 dB` を引いて求めたと見られるが、**実際には周波数を上げると環境損失は下がる**（−0.5 dB）ため、2 行とも 3.4〜3.6 dB ずれていた。⇒ **この表の値は必ず実測で埋める**（150MHz 側は当時から一致しており、ずれたのは測らずに書いた行だけ）。
- 行の中身（ID・座標・アンテナ高・判定）が**潰れずに読める**こと。
- 🔴 **ID は 9 文字以内にする**（2026-08-09）。ID 欄は 16 文字まで受け付けるのに **9 文字ぶんしか見えない**既知の欠陥があり、`asaminami24` と入れると `asaminami2`（または `aminami24`）と表示される＝**値は正しいのに、読み手には別の ID に見える**。⇒ 4 行目を `asa2400` にしてある。⚠️ **欄の幅は文字数でなく字形で決まる**ので `hatsukaichi`（11 文字）は読める。**目視で確かめる**こと。⚠️ **これは絵の側での回避**であって、欠陥は直っていない（複数経路の窓は 150% 表示の FHD で横の余裕が 0px なので、ID 列を広げるには他の列から幅を借りる必要がある）。

### 5 枚目 — 中継経路（`docs/images/shot_multihop.png`）

ランチャーの **中継経路** ボタンで開き、**下の 3 地点**を入れて実行し終えた状態（区間表に結果が返っている）を撮る。

| # | 地点名 | 座標 | アンテナ高 |
|---|---|---|---|
| 送信 | 広島県庁 | `34.3966, 132.4596` | 40 |
| 中継 | 向洋 | `34.3800, 132.5000` | 30 |
| 受信 | 海田町役場 | `34.3714, 132.5347` | 20 |

🔴 **周波数と利得は「区間ごとの設定」に入れる**（2026-08-09 訂正）。この窓の凍結帯（共通設定）に
並ぶのは **送信電力・受信感度・植生高・サンプル数・降雨量・環境区分の 6 つだけ**で、
**周波数と利得はここには無い**（区間ごとに別のアンテナ・別の周波数を使えるのが中継の要件だから）。

| 区間の行 | 周波数 (MHz) | 送信利得 (dBi) | 受信利得 (dBi) |
|---|---|---|---|
| TX → R1 | **2400** | **0** | **0** |
| R1 → RX | **2400** | **0** | **0** |

⚠️ **区間の欄を空欄にしない**＝空欄はランチャーの値を継承するので、**絵の値が撮影時の
ランチャー設定に依存して再現できなくなる**（最初の撮影が実際にそうなり、150MHz・利得 6/6 を
継承した +42.2 / +39.5 の絵になった）。明示的に入れれば**値が画面に写る**ので、
「区間ごとに諸元を変えられる」という中継窓の特徴も同時に伝わる。

凍結帯（共通設定）は **送信電力 37dBm・受信感度 −85dBm・植生 0m・サンプル数 200・見通し**、
回折モデルは Deygout。

| 区間 | 距離 | 期待される結果 |
|---|---|---|
| 県庁 → 向洋 | 4.14km | **OK**（+6.3 dB・遮蔽 0.0%） |
| 向洋 → 海田町役場 | 3.33km | **OK**（+8.2 dB・遮蔽 33.8%） |
| **全体** | | **OK**（最小余裕 **+6.3 dB**） |

- 🔑 **この絵の主題は「直接届かない回線が、中継で成立する」**＝**まったく同じ条件で県庁 → 海田町役場を直接結ぶと −5.7 dB の NG**（4 枚目の条件 3 がそれ）。**4 枚目と 5 枚目は地続き**で、条件探索で「届かない」と分かった回線を中継で救う流れになっている。
- **再生中継なので全体の可否は最も苦しい区間で決まる**（区間の損失は足し合わせない）。区間ごとの内訳が表に出ていることが写っていること。
- 2 区間とも遮蔽率の生値が 100% 以下・起伏 25m 以下＝**発散域に入らない**ことを実測で確認済み。
