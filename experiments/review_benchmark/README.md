# 独立レビューのベンチマーク（2026-07-26 作成）

**目的＝レビュアーを入れ替えたときに、同じ物差しで測る。** 現在の独立レビューは Codex（VS Code 拡張・[[feedback-independent-review]]）が担っているが、「**ローカル LLM に託せるか**」は繰り返し出てくる問い（2026-07-26 にユーザーが提起）。**推測で「無理」と決めず実測する**ためのデータセット。

正解ラベルは [findings.json](findings.json)。**Codex が実際に出した指摘 11 件（全件真）＋ 対照の偽陽性 1 件**（こちらはローカル LLM の doc-review 由来）に、裏取り済みの判定と「本当の欠陥はどこにあったか」を付けてある。

## なぜこのデータセットに意味があるか

- **全件が実測で裏取り済み**（ユーザーと Claude が当時コードを当たって確認）。合成データではない。
- **偽陽性が 1 件入っている**（`F1`＝README のビルド手順。2 回とも同じ誤検知）。**精度を測るには「鳴ってはいけないもの」が要る。**
- **指摘の所在と欠陥の所在がずれる例が 1 件ある**（`D3`＝文書の食い違いとして報告されたが、実害はコードのゲートの登録漏れだった）。**発見と診断は別の能力**なので、そこを分けて採点できる。
- **処方を外した例が 2 件ある**（`C4` / `D3` の `wrong_prescription`）。「発見は Codex・処方は我々」という運用規則の根拠そのもの。

## 走らせ方

```
python experiments/review_benchmark/run_benchmark.py ornith:9b qwen2.5-coder:7b
python experiments/review_benchmark/run_benchmark.py <model> --case C1C2C3
```

`--case` は `C6C7`（既定）/ `C1C2C3` / `C5`。入力は git から自動で組み立てる。
生出力は `runs/`（git-ignore・再生成可能）。**表示される ○ は「言及があった」だけ**なので、
最終判定は本文を読んで [findings.json](findings.json) と突き合わせる。

⚠️ **手で `ollama run` に流さないこと。** `num_ctx` の既定はモデル上限（例: 131072）で、
8GB の GPU では KV キャッシュが載らず**モデルの半分が CPU へ溢れて 5〜10 倍遅くなる**
（2026-07-26 に実際に踏んだ＝360 秒が適正設定で 52 秒）。ランナーは入力実測から
`num_ctx` を選び、thinking も既定で切る（思考は生成の 8 割を占めて結論を変えなかった）。

## 測り方

**⚠️ 観点を指定せずに渡すこと。** 「CSV を見て」「非対称を探して」と言った時点で、測っているのはレビュアーではなく**渡し方**になる。指定してよいのは範囲だけ（コード＝この差分／文書＝正典間の食い違いと状態の陳腐化）。

### コード面（git で完全に再現できる）

各 finding の `defect_state` が**欠陥が存在するコミット**。そこをチェックアウトするか、`input` の差分をそのまま渡す。

```
git diff c4c6c8b..1ca5089     # C1 C2 C3（＋当時の batch.py 全体）
git diff 87fbc46..c4c6c8b     # C4
git diff c4c6c8b..0143e6a     # C5
git diff 1ca5089..2730717     # C6 C7
```

### 文書面（memory は git 管理外なので手で戻す）

`findings.json` の `doc_reconstruction` にある 4 か所を現在の memory へ戻す（作業用のコピーに対して行うこと）。戻したら memory 一式＋README×4＋CHANGELOG を渡す。

## 採点

| 指標 | 数え方 |
|------|--------|
| **検出率（recall）** | 真 11 件のうち何件を指摘したか |
| **精度（precision）** | 出した指摘のうち実在は何件か。`F1` を出したら偽陽性 1 |
| **診断の正しさ** | `D3` で**コード側の欠陥**に到達できたか（文書の書き換えだけを勧めたら Codex と同じ水準） |
| **処方の正しさ** | `C4` で `validate_config` を勧めたら不正解（正解は `validate_value`） |

**⚠️ 検出率は「見つけたもの」しか測れない。** このデータセットに無い欠陥を見逃していても分からないので、**満点でも「安全の証拠」にはならない**（[[feedback-promote-recurring-checks]]「指摘ゼロを安全の証拠にしない」）。
