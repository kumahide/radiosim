# 画面の道具の試作（4.0 ステージ2）

同じ課題＝1 回線を入力→地図→断面図→判定を 1 ウィンドウで・入力したらすぐ計算（地形は端点が決まったときだけ取得）。
計算は `core/` をそのまま呼ぶ。製品のコードと `requirements.txt` は触らない。

| 候補 | 置き場 | 窓 | 画面 |
|---|---|---|---|
| A | `a_pywebview/` | `pywebview`（WebView2） | `web/` |
| B | `b_edge_app/` | Edge のアプリモード（実行時の依存なし） | `web/` |
| C | `c_tk/` | Tk 9（今の道具＝物差し） | `tkintermapview`・`matplotlib` |

- `common/`＝計算の口・タイルの配信（製品と同じディスクキャッシュ）・環境の測定・`127.0.0.1` の HTTP サーバ。
- `web/vendor/leaflet/`＝Leaflet 1.9.4（BSD-2-Clause・`LICENSE` を同梱・npm の shasum を照合済み）。WebGL を使わないラスタ表示。
- 画面の「測定」欄＝会社 PC ではスクショ 1 枚で読む。

## 動かす

製品の外の venv を使う（`D:\dev\radiosim\venv-ui-proto`・親は `D:\tools\py3150`）。

```
D:\dev\radiosim\venv-ui-proto\Scripts\python.exe experiments\ui_proto\a_pywebview\main.py
D:\dev\radiosim\venv-ui-proto\Scripts\python.exe experiments\ui_proto\measure.py --runs 5 --size 1900x950 --out D:\dev\radiosim\ui_proto\measure
```

`--offline` は届かないプロキシを挟み、ネットワークを切った状態を作る。

固める＝`build.py --out D:\dev\radiosim\ui_proto`（`--only a` で 1 つだけ・集計は在る zip を全部数え直す）。
固めた exe を測る＝`measure.py --exe a=<exe> ...`。会社 PC での確認は [CHECK_ja.md](CHECK_ja.md)。

## 所見

- **画面の更新の上限**＝開発機はリモートデスクトップ越し（32 Hz）。A・B の 31 ms と 32 fps はその上限で、道具の差ではない＝比べるのは「書き終え」。C の 65 ms は `matplotlib` の描き直し。
- **大きさ**＝共通の numpy・Pillow が約 37 MB。C はそこへ Tk と `matplotlib`。
- **MOTW**＝印の付いた `Python.Runtime.dll` を .NET Framework が読まず、A だけ起動しなかった（`Failed to resolve Python.Runtime.Loader.Initialize`）。起動の最初に `_internal` の下の DLL から印を外して通した（19 個）。⚠️ 書けない置き場（読み取り専用の共有など）では外せない＝A だけの弱み。B・C は印のままで動く。
- **スマート アプリ コントロール**（開発機はオン）＝署名のない exe を中身ごとに判定する。固め直した B の 1 つ目が止められ（`WinError 4551`・CodeIntegrity の 3077／3118）、もう 1 度固めた B は通った＝3 候補に共通の当たり外れで、製品の exe にも同じことが起こりうる。会社 PC で有効かは未確認。
- **オフライン**（届かないプロキシ）＝3 つとも起動して判定まで届く（既定の端点は地形がキャッシュ済み）。地図は A・B がキャッシュの 21 枚で埋まり、C は範囲が広く未取得の 25 枚を失敗に数える（落ちない）。両端とも未取得の端点＝判定を出さず「地形なし」（約 12 秒で打ち切り）。⚠️ 片端だけキャッシュ済みだと打ち切りが働かず、未取得の標本ごとに通信を試し続ける（約 800 km の経路で 5 分を超えた）＝製品の `core` の不具合で、打ち切りの条件が「成功 0 のまま続けて失敗」だから（`core/simulation.py` の取得のワーカー）。試作の範囲では直さない。
- **言語**＝起動で製品と同じく `i18n.set_lang(config.startup_lang(cfg))` を呼ぶ＝「地形なし」などコアの文が製品と同じ言語で出る。

## 会社 PC（AVD）の実測（2026-11-06）

経営者が「測定」欄を撮った写真から読んだ。条件＝AVD・1920×1080・DPI 1・画面 32 Hz・GPU なし（A・B は `Microsoft Basic Render Driver`・C は GDI）・プロキシは自動構成（欄は空のまま通った）・WebView2 156・Windows 10.0.26200。B の初回は撮り漏らし。

| | A `pywebview` | B Edge のアプリモード | C Tk 9 |
|---|---|---|---|
| 起動→判定（初回） | 18.45 秒 | — | 19.06 秒 |
| 起動→判定（2 回目） | 3.84 秒 | 3.06 秒 | 3.56 秒 |
| 画面→判定（2 回目） | 0.89 秒 | 1.51 秒 | — |
| 入力→判定 中央・95% | 31・33 ms | 31・33 ms | 161・210 ms（初回 200・374） |
| 入力→書き終え 中央 | 20 ms（初回 18） | 9 ms | — |
| 地図を動かす | 33 fps（初回 32） | 31 fps | 1 回 11.7 ms（初回 21.4） |
| 窓の内側・はみ出し | 1920×1057・0 | 1920×1055・0 | 1920×1057・0 |
| タイル 手元・取得・失敗 | 初回 0・21・18／2 回目 21・0・0 | 21・0・0 | 初回 27・0・315／2 回目 27・0・253 |

- **初回の約 15 秒は WebView2 によらない**＝WebView2 を使わない C も 19.06 秒。新しい exe の初回に共通（ウイルス対策の検査の疑い・未確定）＝製品の exe も配るたびに同じことが起こりうる。
- **2 回目は 3 候補とも 3〜4 秒**＝開発機の 3〜6.5 倍。
- **C の入力→判定は 161〜200 ms**＝人が遅れに気づく 100 ms を超える（開発機は 65 ms）＝「入力したらすぐ計算」に足りない。A・B は画面の上限（32 Hz）に張り付き、差は書き終え（A 20 ms・B 9 ms）だけ。
- **タイルの失敗**＝理由はどれも「タイルが返らなかった」（404 以外の非 200・タイムアウト・接続の失敗のどれか。試作は理由を残さない）。A は初回にドラッグで頼んだ分で 18 枚。C は 1 枚も取れず数百（同じ `/tile/` の経路で A・B は取れた）。原因は未確定。
- **使える領域**＝OS の使える領域が画面いっぱい（1920×1080）で、最大化した窓の内側は 1057 px。

経営者の所感（2026-11-06）＝
- **手触り**＝3 候補で特に違いなし（C の入力→判定 161〜200 ms も体感の差にならなかった）。
- **地図の抜け**＝A・B とも、ドラッグの後に白く抜けたマスが残ることがあった。B のほうが安定していた＝プロキシ越しの取得の失敗は道具によらず、製品の地図にも要る手当て。
- **止める画面**＝3 候補とも出た（署名のない exe と、ダウンロードした印による）＝道具の差ではない。

未確認＝B の初回・タイルの失敗の理由（C だけ 1 枚も取れない理由を含む）。

**決定**（2026-11-06 経営者）＝Link 1.0 の画面の道具は **B Edge のアプリモード**。
