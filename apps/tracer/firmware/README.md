# RadioSim Tracer ファーム（XIAO ESP32C6）

実測補助ツール（仮称 RadioSim Tracer）の送受信機のファームです。同じファームを 2 台に書き込み、1 台を送信（TX）、もう 1 台を受信（RX）に設定して使います。

- TX は、番号付きのパケットを一定の間隔（既定 100 ms）で送ります。
- RX は、受け取ったパケットごとに受信レベルの生値を USB へ流します。PC 側の `python -m apps.tracer.cli record` がそれを記録します。
- 送受信のパケットと USB に流すデータの形は、どちらも `apps/tracer/mavlink/radiosim_tracer.xml` で定義しています。

ハードウェアは製品として配布しません。このファームは、測定に使う機材を再現できるようにするためにリポジトリで管理しています。

## 必要なもの

- Seeed Studio XIAO ESP32C6 × 2
- 技術基準適合証明の対象になっている外付けの 2.4 GHz ロッドアンテナ（U.FL）× 2。ファームはアンテナの切り替えを外付け側に固定します。
- ESP-IDF **v6.1**（公式のインストーラ）。ほかの版ではビルドが止まります。測定記録に残るのはファームのコミットだけなので、同じコミットを別の版でビルドできてしまうと、記録から見分けられなくなるためです。版を上げるときは、`CMakeLists.txt` の `TRACER_IDF_VERSION` とこの行を直してコミットしてください。

## ビルドと書き込み

ESP-IDF のコマンドプロンプトで、このフォルダから実行します。

```
idf.py set-target esp32c6
idf.py build
idf.py -p COM5 flash
```

- ファームの版として git のコミット（10 桁）を焼き込みます。版はビルドのたびに取り直すので、コミットを進めたあとは `idf.py build` だけで新しい版になります（`idf.py reconfigure` は要りません）。作業ツリーに未コミットの変更があると、末尾に `-dirty` が付きます。測定に使うファームは、コミットしてからビルドしてください。
- git のコミットが取れない場所ではビルドが止まります（版の分からないファームは測定記録に残せないため）。

`tracer_mavlink.h` は生成物です。手で編集せず、XML を直したらリポジトリの直下で作り直します。

```
python -m apps.tracer.mavlink.gen_c
```

## 設定を変える

USB シリアルに 1 行ずつ送ります（行末は改行）。設定はフラッシュに保存され、変えると再起動します。

| コマンド | 内容 |
|---|---|
| `show` | 今の設定をすぐに送る |
| `role tx` / `role rx` | 送信か受信か（既定は受信） |
| `channel N` | 2.4 GHz のチャネル（1〜13・既定 1） |
| `interval MS` | 送信の間隔（20〜10000 ms・既定 100） |
| `power DBM` | 送信電力（2〜20 dBm・0.25 dB 刻み・既定 15） |
| `cont SEC` | 連続送信を SEC 秒（1〜600）行い、終わったら再起動する。`cont 0` で中止。TX だけ。保存はしない |

- 設定を変えるたびに設定番号（`config_id`）が 1 つ進みます。PC 側は番号でサンプルと設定を結びつけるので、同じ番号が別の設定を指すことはありません。
- TX と RX は同じチャネルに合わせてください。TX は自分の設定を 1 秒ごとに空中へも送り、RX がそれを USB へ中継します。PC 側は TX の設定を中継されたものから取るので、雛形（JSON）には TX の無線設定を書きません。

## 連続送信（送信電力を測るとき）

普段の TX は 100 ms ごとに短いパケットを送るだけなので、平均電力計で測ると実際の送信電力より 15 dB ほど低く出ます。`cont SEC` は、普段と同じ送信の経路と同じ電力の設定のまま、最も長いフレーム（1500 バイト・1 Mbps で約 12 ms）を間を詰めて送り続けます。

- フレームの間には必ず隙間が空くので、ファームは送信完了の時刻から実際の送信時間の割合（デューティ）を測り、1 秒ごとに `CONT duty=… intervals=… other_rate=… …` の行で知らせます。バースト中の電力は「平均電力計の読み − 10·log10(デューティ)」です。`python -m apps.tracer.cli cont` がこの計算と記録を行います。
- `other_rate` が 0 でないときは、1 Mbps 以外で出たフレームがあったのでデューティを使えません。
- 始める前に設定番号（`config_id`）を 1 つ進め、終わったら再起動します。連続送信の間は番号付きのパケットも設定も送らないので、この間を跨いだ記録は、再起動後の新しい設定番号で PC 側が閉じます。
- 設定は保存しません。電源を入れ直せば普段の送信に戻ります。
- PHY の試験モード（連続波など）は使っていません。電力の指定の経路が普段の測定と違い、測った値が測定に使う出力と同じである保証が無いためです。

## USB に流れるもの

- 設定（`TRACER_CONFIG`）：起動時と変更時に加えて、1 秒ごとに送ります。PC 側は同じ設定の再送を読み飛ばすので、RX を先に起動しておいても記録を始められます。RX は、空中で受けた TX の設定もそのまま流します。
- 受信サンプル（`TRACER_RX_SAMPLE`、RX のみ）：受信 1 回ごと。送信機ごとの通し番号（`sample_seq`）を受信した時点で振るので、USB への書き込みやキューで落ちたサンプルは、PC 側で番号の欠けとして分かります。電波で届かなかったパケットには番号が振られないため、この 2 つは区別できます。
- 送信の控え（`TRACER_TX_PACKET`、TX のみ）：送信 1 回ごと。
- コマンドへの返答（`OK ...` / `ERR ...` のテキスト行）と、連続送信の報告（`CONT ...` のテキスト行）。

ログは USB ではなく UART0 のピンに出します。ログの行がデータの途中に割り込むと、そのデータは PC 側で壊れたものとして捨てられ、電波が届かなかった場合と区別できなくなるためです。

起動すると、まず自己検査をします。組み立てたデータが PC 側と 1 バイトでも食い違うと、`ERR 自己検査に落ちました` を 1 秒ごとに送るだけで、測定は始めません。

## 空中のレート

空中のレートは 1 Mbps（11b・ロングプリアンブル）に固定しています。TX は起動するたびに確認用のフレームを 1 つ送り、無線のドライバが実際に使ったレートを確かめます。1 Mbps でなければ測定を始めず、`ERR 空中のレートが 1 Mbps になりません（実際 … kbps）` を 1 秒ごとに送ります。この状態でもコマンドは受け付けるので、`role rx` などで抜けられます。

測定の途中でレートが変わった場合、TX は送信を止めません。止めると、RX には電波が届かなくなったのと同じに見えるためです。代わりに、設定の `rate_kbps` を実際の値に直してすぐに送ります。PC は設定が変わったのを見て、そこでセッションを閉じます。

2 台の実機（2026-09-19・チャネル 1・間隔 100 ms）で確かめたこと:

- TX のドライバが報告するレートと RX が受けたフレームのレートは、どちらも 1 Mbps でした（RX は全フレームが 11b）。
- 以前の指定方法（`esp_wifi_config_80211_tx_rate`）は、ESP-IDF v6.1 では効きません。`esp_wifi_start` の後に呼ぶと成功を返しますが、11 Mbps を指定しても 1 Mbps のまま送られました（ドライバの既定値が 1 Mbps だっただけ）。`esp_wifi_start` の前に呼ぶと失敗します。いまの指定方法（`esp_wifi_config_80211_tx`）で 11 Mbps を指定すると、TX と RX の両方で 11 Mbps になりました。
- わざと 11 Mbps にしたファームでは、TX は `ERR …（実際 11000 kbps …）` を出して測定を始めませんでした。RX には何も届きませんでした。
- 測定の途中で 11 Mbps に切り替えると、RX が中継する TX の設定は次の周期で `rate_kbps=11000` に変わりました。古い刻印のまま届いたのは、切り替えた回のパケット 1 つだけでした。

1 台の実機（2026-09-19）で確かめたこと:

- USB のポートを閉じるとボードがリセットされます。開いたときはリセットされません。
- ポートを開いた直後に最初に届くデータは、閉じていた間に溜まっていた古いものです。

2 台の実機を机の上で対向させて（2026-09-19・ファーム `afd69ae7db`・チャネル 1・間隔 100 ms・15 dBm・10 秒間）確かめたこと:

- 生のフレーム送信（`esp_wifi_80211_tx`）でアクションフレームを送れます。TX が送った 97 パケットを RX がすべて受けました。
- プロミスキャス受信で受信レベルと雑音フロアが取れます（生値で `rssi` −35〜−33・`noise_floor` −92）。
- 1 秒ごとに TX の設定を空中へ送っても、送信間隔は乱れません（RX の受信時刻で中央値 100.0 ms・最小 91.9 ms・最大 108.1 ms）。
- RX は、空中で受けた TX の設定を USB へ中継します。受信サンプルの `tx_config_id` は TX の設定番号と一致しました。
- TX のポートを閉じてリセットすると TX の `seq` は 0 に戻りますが、RX の `sample_seq` は戻らずに続きます。
- USB の欠け（`sample_seq` の飛び）と CRC の不一致は、どちらも 0 件でした。
- アンテナ切り替えのピン（GPIO3 を Low で切り替えを有効に、GPIO14 を High で外付け側）は資料どおりです。RX の外付けアンテナを U.FL から外すと受信レベルが約 45 dB 下がり（生値の中央値で −37 から −88〜−80）、付け直すと戻りました。オンボード側のままなら、外しても受信レベルはほとんど変わりません。

空中に送るパケットの識別子（`radio.c` の `TRACER_AIR_OUI`）は仮の値で、登録された値ではありません。
