# 段0 の机上試験の手順（RadioSim Tracer）

2 台の送受信機（A・B）を同軸とアッテネータでつなぎ、実際の測定に入る前に次のことを確かめます。

- 基板からの漏れが無いこと
- 受信レベルの読みが入力に比例し、1 dB 刻みの値が十分に散ること（ディザ）
- 受信率が入力レベルに対してどう落ちるか（打ち切りのしきい値と感度を決める材料）
- 送信電力の設定が出力どおりに効くこと
- 2 台の個体差

測定は両方向（A→B と B→A）で行います。役割はコマンドで入れ替えるので、配線に触らずに両方向を測れます。2 台とも送信と受信の両方の校正値を持つので、現場ではどちらをどちらに使っても構いません。

段0 は 2 回に分けて行います。

- **段0a（手元）**: 読みの形、線形性、ディザ、受信率、個体差を調べます。ここで分かるのは相対的な値だけです。
- **段0b（校正済みの測定器がある場所）**: 2 台の送信出力を測定器で測ります。これで絶対値が決まり、個体ごとの校正ファイルが作れます。

生のデータはすべて残るので、段0b の実測値が分かったら、段0a を測り直さずに計算し直せます。0a と 0b はどちらを先に行っても構いません。

## 機材

| 機材 | 備考 |
|---|---|
| XIAO ESP32C6 ×2 | ファームは `firmware/README.md` の手順で書き込みます |
| U.FL→SMA ピッグテール ×2 | 一度付けたら外しません。この SMA 端が送信出力の基準面です |
| 固定アッテネータ 30 dB ×2 | 大きな入力で受信側が飽和しないようにします |
| ステップアッテネータ（10 dB 刻み 0〜110・1 dB 刻み 0〜11） | 線形性の物差しになります。確度の分かる機械式を使ってください |
| シールドボックス ×2 | 金属缶でも構いません |
| 50 Ω 終端器 ×2 | 漏れの確認に使います |
| SMA ケーブル一式・USB ケーブル ×2・フェライトコア | USB ケーブルは箱の外へ出します |
| （推奨）記録できる温度計・SMA トルクレンチ | |

## 構成

```
[箱A: XIAO-A]─SMA─[30dB]─[30dB]─[ステップ 0-110]─[ステップ 0-11]─SMA─[箱B: XIAO-B]
     │USB                                                                 │USB
     └──────────────────────────── PC ─────────────────────────────────────┘
```

2 台とも USB で PC につなぎます。USB ケーブルが箱の外に出るので、最初の漏れの確認に合格することが前提です。合格しない場合は、送信側を電池で動かして箱に密閉する構成に切り替えてください。その構成では役割の入れ替えを手で行います。

## 段0a の手順

準備として、Tracer の依存を入れておきます（リポジトリの直下で実行します）。

```
python -m pip install -r requirements-tracer.txt
```

計画を変えたいときだけ、雛形を書き出して編集します。省略すると既定の計画で測ります。

```
python -m apps.tracer.cli bench plan plan.json
```

測定を始めます。

```
python -m apps.tracer.cli bench run --port-a COM3 --port-b COM4 --root 測定データ
```

スクリプトが次の順に進めます。画面に指示が出たら、アッテネータを回すか終端器を付け替えて Enter を押してください。`q` を入力すると止まります。止まるまでの記録は残ります。

1. **2 台の確認**: 個体 ID とファームの版を記録します。2 台の版が違う場合は止まります。
2. **漏れの確認**: 2 台の SMA 端に終端器を付けた状態で、両方向とも 1 つも受からないことを確かめます。指示は 2 回（付けるときと外すとき）です。
3. **温め**: 向きを交互に入れ替えながら、受信レベルの平均が落ち着くまで待ちます（最長 30 分）。
4. **粗い掃引**: ステップアッテネータを 0〜110 dB まで 10 dB ずつ変えます。
5. **細かい掃引**: 受信率が落ち始めた段の前後を 1 dB ずつ変えます。範囲はスクリプトが決めます。
6. **電力の掃引**: 感度から十分に離れた減衰量で、送信電力を 3〜20 dBm の範囲で切り替えます。減衰量はスクリプトが決めます。
7. **チャネル**: チャネル 1・7・13 で同じ測定をします。

各段でスクリプトが両方向を続けて測るので、アッテネータを回す回数は片方向だけ測る場合と同じです（合計 30 回ほど、全体で 1 時間強）。一部の段だけ測り直すときは `--only coarse,fine` のように指定します。

測り終えたら判定します。何度でもやり直せます。

```
python -m apps.tracer.cli bench analyze 測定データ/bench-<日時>
```

判定の結果はフォルダの中の `report.md` と `report.json` に残ります。段0a だけでは入力の値が公称（設定した電力と公称の損失から計算した値）になるので、dBm の校正ファイルは作りません。

## 段0b の手順

実測値を書くファイルの雛形を作ります。

```
python -m apps.tracer.cli bench ref ref.json
```

**送信出力**: 1 台ずつ SMA 端を測定器につなぎ、連続送信で測ります。測定器の読みを入力すると、`ref.json` に結果が追記されます。

```
python -m apps.tracer.cli cont --port COM3 --seconds 60 --ref ref.json
```

- 受信側に設定されている機器は、自動で送信側に切り替わります。
- 連続送信でも、フレームの間には必ず隙間があります。ファームが実際の送信時間の割合（デューティ）を測っているので、平均電力計の読みから、バースト中の電力が自動で計算されます。ピーク電力やバースト電力を測れる測定器なら、`--reading burst` を付けてください。
- 測定器の前に減衰器を入れた場合は、`--pad-db 20` のようにその値を指定します。
- 2 台とも、実際の測定で使う電力とチャネルで測ってください。チャネルを変えて使う予定があれば、そのチャネルでも測ります。

**損失の実測値**: 固定アッテネータとケーブルの損失の合計を `ref.json` の `fixed_loss_db` に書きます。ステップアッテネータの各段の実測値は、`step_attenuator` の `tens`（10 dB 刻みのつまみ）と `ones`（1 dB 刻みのつまみ）に書きます。書かなかった段は公称値のまま計算します。

**信号発生器（任意）**: 11b の信号を出せる信号発生器があれば、受信側に既知のレベルを直接入れて、その読みを `rx_direct` に書きます。送信側の経由で求めた値と突き合わせるので、もう一方の経路で確かめられます（閉合チェック）。

最後に、判定をやり直して校正ファイルを作ります。

```
python -m apps.tracer.cli bench analyze 測定データ/bench-<日時> --ref ref.json --calib-dir 校正
```

`校正/<個体 ID>.json` が 2 台分できます。受信の校正値と、電力・チャネルごとの送信出力の表が入っています。表の各行には、測定器で直接測った値（`meter`）か、電力の掃引の相対差から導いた値（`bench_power_sweep`）かが書かれています。

## 実際の測定での使い方

記録するときに校正ファイルのフォルダを指定すると、雛形に書いた個体 ID で校正ファイルを読み、セッションに写します。雛形に校正値を書く必要はありません。

```
python -m apps.tracer.cli record --template 雛形.json --port COM5 --root 測定データ --calib 校正
```

送信側の出力は、実際に動いている電力とチャネルの行から選ばれます。その行が校正ファイルに無い場合は、記録を始めません。

## 判定の目安

`report.md` には目安との比較が並びます。打ち切りのしきい値、感度、窓の最小件数を最終的に決めるのは作業者です。

| 項目 | 目安 |
|---|---|
| 漏れ | 終端した状態で 1 つも受からない |
| 線形性 | 線形域での最大のずれが 1 dB 以内 |
| ディザ | 受信率 99% 以上の段で、読みが 2 種類以上の値に散る |
| 閉合チェック | 2 つの経路の差が ±1 dB 以内 |
