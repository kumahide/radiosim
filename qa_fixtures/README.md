# qa_fixtures — 動作確認用の設定ファイル置き場

動作確認のたびに手で書いていた設定ファイルの**正本**を置く場所です。ビルドの成果物
（`dist/`）はビルドのたびに作り直されるので、そこへ直接置いた設定は毎回消えます。
ここに置いて、ビルド後に配ってください。

```powershell
& "$env:RADIOSIM_PYTHON" buildtools\deploy_qa_fixtures.py            # dist\RadioSimPro\ へ配る
& "$env:RADIOSIM_PYTHON" buildtools\deploy_qa_fixtures.py --repo     # ソースから起動して確認する場合
& "$env:RADIOSIM_PYTHON" buildtools\deploy_qa_fixtures.py --appdata  # インストーラ版で確認する場合
& "$env:RADIOSIM_PYTHON" buildtools\deploy_qa_fixtures.py --remove   # 配ったものを片付ける
```

⛔ **`build.bat` からは呼びません。** ビルドの途中で配ると、確認用の設定が配布 zip や
インストーラに入ってしまいます。配るのは「ビルドが終わった後の、確認する人の手元」だけです。

## 中身と、それぞれが何を確かめるためのものか

### `dem_sources.toml` — DEM ソースを足した状態を作る

2 件とも**妥当な宣言**です（起動時の通知に誤りは出ません）。

| `source_id` | 何のために置いているか |
| --- | --- |
| `terrarium_aws` | 実際に標高を取れる外部ソース（AWS Open Data Terrain Tiles・鍵不要）。国土地理院の範囲外＝日本国外で標高が取れることの確認に使います。 |
| `qa_offline_probe` | **通信が必ず失敗する当て馬**（ホスト名は例示用の予約ドメイン）。選択肢を 3 つ（国土地理院とこの 2 件）にして欄の見え方を確かめること、取得失敗が「DEM 取得失敗率」に出ることの確認用です。表示名をわざと長くしてあるのは、地図ウィンドウの「対象 DEM ソース」欄の幅が中身に追従することを確かめるため（この欄は以前、ウィンドウの右端で見切れていました）。 |

これを配ると、ランチャーの「環境」グループに **DEM ソース** 欄が現れ、地図ウィンドウの
キャッシュ管理モードに **対象 DEM ソース** 欄が現れます（どちらも、ソースが国土地理院
だけのときは欄自体が出ない仕様のため、この設定が無いと確認できません）。

**誤った宣言をはじくこと**を確かめたいときは、このファイルを直接いじらず、コピーを
壊して使ってください（壊し方の例はファイル内のコメントに書いてあります）。正本が
壊れていると、他の確認をするたびに毎回エラー通知が出ます。

### `tile_sources.toml` — 背景地図ソースを足した状態を作る

`osm`（OpenStreetMap）1 件。地図ウィンドウ上部の背景選択に組み込みの 2 択（淡色地図・
航空写真）に加えて現れ、国土地理院の範囲外でも背景地図が出ることを確認できます。

⚠️ OpenStreetMap のタイルは公共サーバなので、**広い範囲の事前取得（キャッシュ管理の
ダウンロード）には使わないでください**（利用規約に反します）。画面に出る範囲を眺める
程度に留めてください。

### `lang/qa_fr.json` — 利用者が足す表示言語を再現する

内容は `docs/manual_ja.md`「表示言語を自分で足す」の例と同じ書式＝`_name`（言語
メニューに出す名前）＋一部のキーだけの訳（`menu_help`・`btn_run`・差し込み `{path}`
付きの `proj_saved`）。**わざと一部だけ**にしてあります＝訳していないキーが英語の
まま出る（フォールバック）ことも、この 1 件で確認できるように。

これを配ると、設定 > 言語のメニューに **QA Français** が増えます。開くとヘルプ
メニューと実行ボタンなどごく一部だけがフランス語になり、残りは英語のままです
（正しい振る舞い＝「全部を訳す必要はない」という利用者拡張の設計どおり）。

⚠️ **置き場が他の 2 件と違う**＝`dem_sources.toml` 等の「配置先の直下」ではなく、
**配置先の `lang` サブフォルダの下**（`core.config.USER_LANG_DIR` 基準＝ポータブル
配置ではアプリの隣の `lang`、インストーラ版では `%APPDATA%\RadioSim\lang`）。
`--repo` / 既定（`dist\RadioSimPro\`）/ `--appdata` のどれで配ってもこの基準に
従って正しい置き場へ入ります（配布道具がフォルダを自動で作ります）。

**壊し方を確かめたいとき**（このファイルを直接いじらず、コピーしてから壊す）:
- 英語に無いキーを足す → 却下されアプリは起動する（`lang_ext_why_unknown`）
- `{path}` を消す／別の差し込み名にする → 却下される（`lang_ext_why_placeholder`）
- ファイル名を `ja.json` や `en.json` にする → 同梱言語として上書き不可で却下される
  （`lang_ext_why_builtin`）

いずれも「その言語だけが使えない・アプリは起動する」ことと、設定 > 言語のメニュー
に却下の通知が出ることを確認する。

## 追加するとき

- 製品が読む名前のファイルを足したら、`buildtools/deploy_qa_fixtures.py` の
  `FIXTURE_FILES` にも足してください（このディレクトリの中身を丸ごと配らないのは、
  この README や壊した実験用のコピーを一緒に配らないためです）。
- 宣言ファイルは**書式が版とともに変わり得ます**。`tests/test_qa_fixtures.py` が製品の
  読み込み器で実際に読んで検証しているので、書式が変わればテストが落ちて気づけます。
